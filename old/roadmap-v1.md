# ロードマップ — 全20章の地図

全体を 5 部・20 章に分割します。
各章は独立したマイルストーンで、**章の終わりには必ず「前より賢くなった動くコンパイラ」が残ります**。

進捗は「状態」列で管理します（⬜ 未着手 / 🔨 作業中 / ✅ 完成）。

---

## 全体像

```
第I部  電卓を作る          (ch1-3)   ── コンパイラの骨格を通す
第II部 言語らしくする      (ch4-8)   ── 文・変数・型検査・制御構文・関数
第III部 データを扱う       (ch9-12)  ── 文字列・リスト・ループ・クラス
第IV部 実用言語にする      (ch13-15) ── モジュール・標準ライブラリ
第V部  セルフホスト        (ch16-20) ── Polonium で Polonium を書く
```

---

## 第I部 電卓を作る — コンパイラの骨格を通す

まず「Lexer → Parser → Codegen → LLVM」という**パイプライン全体を最短で貫通**させます。
機能は貧弱でも、端から端までつながっていることが何より重要です。

### ✅ 第1章 環境構築と最小コンパイラ
- **達成目標**: `42` と書いたファイルをコンパイルし、終了コード 42 で終わる実行ファイルを作る
- 学ぶこと: LLVM IR の読み書き / トークン列 / 再帰下降パーサの最小形 / AST / IR 出力
- 成果物: `src/{main,util,lexer,ast,parser,codegen}.c`、`Makefile`、`tests/run_tests.sh`
- [→ 第1章](chapters/ch01-setup-and-minimal-compiler.md)

### ✅ 第2章 四則演算と演算子の優先順位
- **達成目標**: `2 * 3 + (10 - 4) * 6` が正しく計算できる
- 学ぶこと: 演算子の優先順位と結合性 / 文法を階層化する技法 / 単項演算子 / 最長一致
- 成果物: 14 種類の演算子、8 個の文法関数、16/8/2 進リテラル、テスト 34 件
- 注記: `**` は負の指数を実行時エラーにする必要があるため第9章に延期
- [→ 第2章](chapters/ch02-arithmetic-and-precedence.md)

### ✅ 第3章 エラー報告と診断メッセージ
- **達成目標**: 「関連する位置」とヒントを添えた診断を出せるようにする
- 学ぶこと: 診断の3要素 / 循環依存の回避 / 仮想トークンの位置 / UTF-8 の表示幅
- 成果物: `src/diag.{h,c}` 新設、`expect_close()`、テストランナー強化、テスト 36 件
- [→ 第3章](chapters/ch03-diagnostics.md)

```
error: 閉じ括弧 ')' がありません
  --> t.po:2:7
   |
 2 | (1 + 2
   |       ^ ここに ')' が必要です
   |
note: 対応する '(' はここです
  --> t.po:2:1
   |
 2 | (1 + 2
   | ^
   |
   = ヒント: 括弧の対応を確認してください
```

## 第II部 言語らしくする

### ✅ 第4章 インデント構文（NEWLINE / INDENT / DEDENT）
- **達成目標**: 複数行のプログラムを読み、インデントからブロック構造を検出できる
- 学ぶこと: オフサイドルール / インデントスタック / 論理行と物理行の違い / 空行とコメントの扱い
- **ここが Python 風言語の一番の山場**です。字句解析器が「仮想トークン」を合成します。
- 成果物: `scan_indent` / `emit_indent_tokens`、`ND_BLOCK`、テストランナーの `# TOKENS:`、テスト 46 件
- 注記: `INDENT`/`DEDENT` を消費する構文（if/while）は第7章。この章は**生成側**を作り、`--dump-tokens` で検証する
- [→ 第4章](chapters/ch04-indentation.md)

### ✅ 第5章 変数と型検査パスの導入
- **達成目標**: `x: int = 1` / `x = x + 2` / 最後の式文 `x` が動く。未定義の名前・未知の型名はコンパイルエラー
- 学ぶこと: シンボルテーブル / スコープ / `alloca`・`store`・`load` / **意味解析パス（sema.c）の新設**
- 成果物: `src/types.{h,c}`・`src/sema.{h,c}` 新設、`peek_at()` による 2 トークン先読み、複合代入の脱糖、テスト 61 件
- 注記: `/` と 0 除算の検査を codegen から sema へ移動。型が `int` 1 つしかないため「型不一致」のテストは第6章から
- [→ 第5章](chapters/ch05-variables-and-typecheck.md)

### ✅ 第6章 bool・比較演算・論理演算
- **達成目標**: `x < 10 and not (x == 3)` が動く。`and`/`or` は短絡評価
- 学ぶこと: `i1` と `i8` の使い分け / 短絡評価のための基本ブロック分岐 / 比較命令 `icmp`
- 成果物: `ND_LOGICAL`、階層の上に 4 段（`or`/`and`/`not`/`comparison`）、
  `emit_label`/`emit_br`/`emit_cond_br`、alloca 専用バッファ、テスト 87 件
- 注記: **初めて制御フローを生成する章**。`mem2reg` が `alloca` を `phi` に変換することを実測。
  第5章で未テストだった「型が一致しません」をここで回収。比較連鎖は構文エラー（Python との差異）
- [→ 第6章](chapters/ch06-bool-and-logical-ops.md)

### ✅ 第7章 制御構文（if / elif / else / while）
- **達成目標**: FizzBuzz の制御構造が書ける（`print` は int 専用の暫定実装）
- 学ぶこと: 基本ブロック / `br` 命令 / 制御フローグラフ / `break`・`continue` のジャンプ先管理
- 成果物: `block()`（**第4章の INDENT / DEDENT を消費**）、`expect()`、`if`/`while`/`break`/`continue`/`pass`、
  `print` の暫定実装、ブロックスコープ、IR 名の一意化、`dead.N`（R7）、テスト 118 件
- 注記: FizzBuzz の**言葉**（"Fizz"）は `str` が要るので第9章。この章では負の数で代用。
  第5章の「変数名がそのまま一意な IR 名」という前提が兄弟スコープで崩れ、sema が名前を割り当てる方式に変更
- [→ 第7章](chapters/ch07-control-flow.md)

### ✅ 第8章 関数定義と呼び出し
- **達成目標**: 再帰でフィボナッチが計算できる
- 学ぶこと: 関数シグネチャの登録（前方参照） / 呼び出し規約 / 引数の `alloca` へのコピー / 戻り値の型検査 / 「全経路で return するか」の検査
- 成果物: `def` / 引数 / `return` / 呼び出し、意味解析の 2 パス化、`always_returns()`、
  `TY_NONE`、グローバル変数（`@g.x`）、テスト 148 件
- 注記: **暫定の足場を 3 つ撤去する章**（暗黙 main / 末尾の式 / print 文）。
  既存テスト 118 件を `def main() -> int:` 形式に移行した
- [→ 第8章](chapters/ch08-functions.md)

## 第III部 データを扱う

### ✅ 第9章 文字列と C ランタイム連携
- **達成目標**: `print("hello")` / `"a" + "b"` / `len(s)` が動く。**FizzBuzz が本物になる**
- 学ぶこと: グローバル定数の出力 / 文字のエスケープ / **`runtime/runtime.c` の新設** / `malloc` / 規約 R10
- 成果物: `runtime/runtime.c`（17 関数）、`TY_STR`、組み込み関数の表、
  文字列の連結と内容比較、テスト 176 件
- 注記: 第2章から先送りしていた **`**`** と **0 除算の実行時検査**もここで回収。
  「複雑さは IR ではなくランタイムに押し出す」（R10）を実践する章
- [→ 第9章](chapters/ch09-strings-and-runtime.md)

### ✅ 第10章 list[T]（動的配列）
- **達成目標**: `xs: list[int] = []` / `xs.append(1)` / `xs[0]` / `len(xs)` が動く
- 学ぶこと: ジェネリック型の型検査 / ヒープ上のデータ構造表現 / 境界検査 / 参照セマンティクス
- 成果物: `TY_LIST` と **`type_equal()` の再帰比較**、型注釈の木（`ND_TYPEREF`）、
  添字とメソッド、`PlList`（倍々に伸びる）、テスト 201 件
- 注記: **第5章の「`a == b` は第10章で壊れる」という予告が現実になる章**。
  再帰比較なしだとコンパイルが通って実行時に segfault することを実測で確認した
- [→ 第10章](chapters/ch10-list.md)

### ✅ 第11章 for 文と range
- **達成目標**: `for i in range(10):` / `for x in xs:` が動く
- 学ぶこと: 構文糖の脱糖（desugaring）— for を while に書き換える
- 成果物: `for_stmt()` の脱糖、`ND_WHILE.incr`（continue の飛び先）、
  隠し変数の命名、テスト 222 件
- 注記: **新しいノード種別を 1 つも作らずに機能を増やす章**。
  第7章の予告どおり「continue が増分を飛ばして無限ループ」の落とし穴を踏み、実測で確認した。
  `str` を回せるのは `len()` と `[]` が str にも使えるおかげ（for 側は無変更）
- [→ 第11章](chapters/ch11-for-and-range.md)

### ✅ 第12章 class（構造体とメソッド）
- **達成目標**: `class Token:` にフィールドとメソッドを定義して使える
- 学ぶこと: 構造体型の IR 定義 / フィールドオフセット計算 / `self` / コンストラクタ / 名前修飾（マングリング）
- 成果物: `TY_CLASS`（**定義の同一性**で比較）、`layout_class()`、`getelementptr`、
  `@Token.show` の名前修飾、`pl_check_not_none()`、テスト 260 件
- 注記: **利用者が新しい型を作れるようになる最初の章**。
  レイアウト（size / offset / align）は自前で計算し、
  `ptrtoint`＋`getelementptr` のイディオムで **LLVM 自身に検算させて一致を実測**した。
  `self` は「暗黙に足す」のではなく**明示的に書かせて検査する**ほうが実装が小さくなった。
  `T | None`（nullable）は**フロー依存の型の絞り込みが要る**ため第15章に送った
- [→ 第12章](chapters/ch12-class.md)

## 第IV部 実用言語にする

### ✅ 第13章 モジュールと import
- **達成目標**: `import lexer` で複数ファイルに分割できる
- 学ぶこと: 複数ファイルのコンパイル / シンボルの可視性 / 名前修飾 / リンク
- 成果物: `module.c`（import をたどる読み込みと循環検出）、モジュールごとのシンボル表、
  `@lexer.Token.show` の 2 段修飾、モジュールごとの `.ll` とリンク、テスト 280 件
- 注記: **1 ファイル = 1 モジュール = 1 名前空間 = 1 つの .ll**。
  式の側は構文解析器を 1 行も変えず、「'.' の左がモジュールか」を意味解析で判断した。
  第12章で `type_equal` を**定義の同一性**にしておいたので、
  `a.Box` と `b.Box` は何もせずに別の型になった（予告の回収）。
  診断は第1章の「位置情報はトークンが持つ」設計のおかげで**無変更**
- [→ 第13章](chapters/ch13-modules.md)

### ✅ 第14章 標準ライブラリ
- **達成目標**: 文字列操作・ファイル入出力・`dict` 相当が使える
- 学ぶこと: 言語機能とライブラリの境界線の引き方 / Polonium 自身で書けるものは Polonium で書く
- 成果物: `extern def`、ランタイムの入出力・`argv`・`system`、`lib/` の探索、
  `lib/strings.po`（120 行・C は 1 行も無い）/ `io.po` / `sys.po` / `dict.po`、
  `examples/wordcount.po`、テスト 292 件
- 注記: **この章の成果物のほとんどは Polonium で書かれている**（コンパイラ本体の変更は 175 行）。
  第13章の `import` があるおかげで、標準ライブラリを言語に埋め込まずに済んだ。
  自分の言語でライブラリを書いたことで**言語の穴が 6 件見つかり**、
  [self-hosting.md](../docs/design/self-hosting.md) 3.6 節に記録して第15章の入力にした。
  `strings.substr` が O(n²) であることは実測で確認済み（直すのは第20章の後）
- [→ 第14章](chapters/ch14-stdlib.md)

### ✅ 第15章 セルフホスト準備（T | None と棚卸し）
- **達成目標**: 「コンパイラを Polonium で書くのに何が足りないか」のチェックリストを完成させ、穴を埋める
- 学ぶこと: ブートストラップの計画立案 / 言語機能の必要十分性の見極め /
  **`T | None` とフロー依存の型の絞り込み（narrowing）**（第12章から移動）
- 成果物: `TY_OPT` / `TY_NULL`、`type_assignable`、絞り込み（if / while / and / ガード節）、
  未初期化フィールドの静的検査、**str の表現変更（長さ付き）**、`byte_at` / `join`、テスト 312 件
- 注記: **新機能を思いつく章ではなく、記録から拾って潰す章**。
  nullable は「フラグ」ではなく「別の型の種類」にした（書き忘れがすり抜けないため）。
  第14章で記録した「s[i] が遅い」を実測したところ**疑っていた原因（確保）は主犯ではなく**、
  真犯人は `len` が O(n) だったこと。str の表現を長さ付きに変えて O(1) にした
- [→ 第15章](chapters/ch15-nullable.md)

## 第V部 セルフホスト

ここから先は、**同じコンパイラを Polonium で書き直す**作業です。
C 版（stage0）が正解を持っているので、常に出力を比較しながら進められます。

### ✅ 第16章 Polonium で字句解析器を書く
- 成果物: `selfhost/token.po` / `selfhost/lexer.po` / `selfhost/dump_tokens.po`、
  `tests/selfhost.sh`（`make test` に組み込み）
- 検証: 同じ入力に対し、C 版と Polonium 版のトークン列が完全一致する
  → **338 ファイルでバイト単位一致・字句エラーの位置も 9 件一致**
- 注記: **機械的に移植し、改善しない**（違いが出たとき原因を 1 種類に絞るため）。
  ポインタ→添字、enum→int 定数、部分文字列はコピー。
  第15章で `str` に長さを持たせていなければ **131 倍遅かった**（実測）。
  C 版の約 2 倍の速度で動く（1.66MB を 0.48 秒）
- [→ 第16章](chapters/ch16-selfhost-lexer.md)

### ✅ 第17章 Polonium で構文解析器を書く
- 成果物: `selfhost/ast.po`（376 行）/ `selfhost/parser.po`（1034 行）/ `selfhost/dump_ast.po`
- 検証: AST のダンプ（S 式形式）が C 版と一致する
  → **AST 一致 304 件・構文エラーの位置一致 37 件**。3 つの脱糖（elif / 複合代入 / for）が
  隠し変数の連番まで一致
- 注記: **C 版のバグを 3 件発見して修正した**（`--dump-ast` が `import` で落ちる、
  `ND_NONE` が改行を出さない、**利用者が `t0` という変数を書くと一時値 `%tN` と衝突する**）。
  一時値の名前は `%t.N` にした（'.' は利用者が書けない。第11〜13章と同じ手口）。
  第15章の `T | None` が無ければ書けない章だった
- [→ 第17章](chapters/ch17-selfhost-parser.md)

### ✅ 第18章 Polonium で型検査器を書く
- 成果物: `selfhost/diag.po`（295 行）/ `types.po` / `module.po` / **`sema.po`（1949 行）**、
  C 版の `--check`、`lib` の `eprint` / `getenv`
- 検証: **型エラー 136 件のメッセージが 1 バイトも違わず一致**、
  正常系 173 件がどちらも素通り
- 注記: 循環 import を禁止した代償が出た章。C 版で 3 ファイルに分かれていた
  Type / Class / シンボル表を、依存が一方通行になるように置き直した
  （`Class.owner` は参照ではなく**モジュール名**で持つ）。
  **C 版のバグを 1 件発見**（`entry` という変数名が LLVM のラベルと衝突。第1章から）
- [→ 第18章](chapters/ch18-selfhost-sema.md)

### ✅ 第19章 Polonium でコード生成器を書く
- 成果物: `selfhost/codegen.po`（1180 行）/ `selfhost/emit_ir.po`、`lib` の `print_raw`
- 検証: **IR 一致 174 件**（一時値・ラベル・`@.str` の連番、declare の順序まで）、
  **stage1 が出した IR で 156 件の実行結果が一致**
- 注記: stage1 が**自分自身の全ソース（約 5,700 行）から 27,216 行の IR** を生成し、
  C 版と 1 バイトも違わなかった。第20章のブートストラップに必要なものは
  「`.ll` を書いて clang を呼ぶドライバ」だけになった。
  この章では C 版のバグが 1 件も出なかった（codegen は全テストが通る場所なので当然）
- [→ 第19章](chapters/ch19-selfhost-codegen.md)
- 検証: 生成される `.ll` が C 版と一致する

### ✅ 第20章 ブートストラップと不動点検証
- **達成目標**: セルフホスト達成
- 手順:
  ```
  stage0 (C製)      + selfhost/*.po  →  stage1 バイナリ
  stage1 (Polonium製) + selfhost/*.po  →  stage2 バイナリ
  stage2 (Polonium製) + selfhost/*.po  →  stage3 バイナリ
  ⇒ stage2 と stage3 が完全一致すれば、不動点に到達＝セルフホスト成功
  ```
- 学ぶこと: なぜ stage1 と stage2 は一致しなくてよいのか / 不動点（fixed point）の意味
- 成果物: `selfhost/main.po`（ドライバ）、`tests/bootstrap.sh`、
  `make bootstrap` / `make bootstrap-test`、`lib` の `remove`
- 検証: **stage2 と stage3 が出す IR が完全一致（13 本）**、
  実行ファイルも UUID を除いてバイト単位で一致、
  **stage2（Polonium 製コンパイラ）でテスト 323 件が全部通る**
- 注記: 最初の比較は失敗したが、違いは macOS のリンカが埋める `LC_UUID` の
  16 バイトだけだった（**「違いが出た」で止まらず「どこが違うか」を見る**）。
  自分自身のコンパイルにかかる時間は C 版と 4% 差（clang の呼び出しが支配的）
- [→ 第20章](chapters/ch20-bootstrap.md)

### 追補（2026-08-26）：セルフホストが見つけた課題を直した

移植中に踏んで記録だけしていた 3 症状（原因は 2 つ）を、**C 版と Polonium 版の両方**で直しました。

| 症状 | 見つけた章 | 直した場所 |
|---|---|---|
| `while True:` を「抜けない」と判定しない | ch16 | `always_returns` |
| `panic` が「戻らない」と扱われない | ch17 | 同上 |
| 絞り込みが `or` / 条件式の途中 / `panic` の後で効かない | ch18 | 同上 ＋ `check_logical` / `narrow_apply` |

**★ 型検査を 2 か所で緩めても不動点は動きませんでした**（`make bootstrap` / `make bootstrap-test`）。
