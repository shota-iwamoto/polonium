# 第11章 for 文と range

> **この章のゴール**
> `for` が書ける。**そして「新しい機能を足さずに機能を増やす」方法を学ぶ。**
>
> ```bash
> $ cat t.po
> def main() -> int:
>     xs: list[int] = [10, 20, 30]
>     for x in xs:
>         print(x)
>     for i in range(3):
>         print(i)
>     return 0
> $ ./build/poloniumc t.po -o t && ./t
> 10
> 20
> 30
> 0
> 1
> 2
> ```

**この章の主題は「構文糖（syntax sugar）」です。**

`for` は**新しい機能ではありません**。`while` の書き方を変えたものにすぎません。

```python
for x in xs:              i: int = 0
    BODY          ⟺      while i < len(xs):
                              x = xs[i]
                              BODY
                              i += 1
```

**この等価性を構文解析器の中で実行してしまえば、
意味解析器もコード生成器も `for` を知らずに済みます。**

第5章の複合代入（`x += e` → `x = x + e`）、
第7章の `elif`（`else` の中の `if`）と同じ手です。
**3 度目なので、もう手癖になっているはずです。**

**⚠️ ただし、この章には落とし穴があります。**
素朴に脱糖すると **`continue` で無限ループになります**（11.4 節）。

## 11.1 脱糖の設計

### 📖 何に書き換えるか

```python
for x in xs:
    BODY
```

```python
# 脱糖後（イメージ）
for.it.0 = xs             # ★ 対象は 1 回だけ評価する
for.ix.0: int = 0
while for.ix.0 < len(for.it.0):
    x = for.it.0[for.ix.0]
    BODY
    for.ix.0 += 1         # ★ ここが continue の飛び先（11.4 節）
```

**⚠️ 対象（`xs`）を 1 回だけ評価する**のが要点です。

```python
for x in make_list():     # ← 毎回呼んだら大変なことになる
```

だから隠しの変数に受けます。**第5章の複合代入で
「左辺は 1 回だけ評価」を気にしたのと同じ話**です。

### 📖 str も同じ形で回せる

```python
for c in "abc":
    print(c)
```

**`len()` と `[]` は `str` にも使えます**（第9・10章）。
だから**上の脱糖がそのまま通用します。** `for` 側に特別扱いは要りません。

**★ 「既にある機能の上に乗せる」と、新しい章の作業が減ります。**

## 11.2 2 つの小さな下ごしらえ

脱糖を構文解析器でやるには、2 つだけ足りないものがあります。

### ✍️ ① 型注釈のない変数宣言（コンパイラ内部用）

```python
x = for.it.0[for.ix.0]
```

このとき `x` の型は**要素型**ですが、**構文解析器は型を知りません。**

そこで `ND_VARDECL` の `type_ref` が `NULL` なら
**「初期化式の型をそのまま使う」**ことにします。

```c
static void check_vardecl(Sema *s, Node *n) {
    Type *declared;
    if (n->type_ref) {
        declared = resolve_type(n->type_ref);
        ...
    } else {
        // ★ 型注釈なし = コンパイラが作った宣言（for の脱糖）。
        //   初期化式の型をそのまま使う。
        // ⚠️ 利用者が書く宣言では parser が必ず type_ref を作るので、
        //    「型注釈は必須」（言語仕様 3.3）は破られません。
        declared = check_expr(s, n->rhs);
        ...
    }
```

**⚠️ これは「型推論を入れた」わけではありません。**
利用者が書く宣言は、構文解析器が必ず型注釈を要求します。
**この抜け道を通れるのは、構文解析器が自分で作ったノードだけ**です。

言語仕様も「ループ変数は型注釈は不要（要素型から決まる）」と決めているので、
**仕様どおりの動作**でもあります（5.5 節）。

### ✍️ ② while に「増分」の枠を足す

```c
    // ND_WHILE の増分処理（第11章）。for の脱糖でだけ使う。
    // ★ C の for(init; cond; incr) の incr にあたるもの。
    //   ここに置くと continue の飛び先を「増分」にできます（11.4 節）。
    Node *incr;
```

**これが無いと `continue` が壊れます。** 次の節で見ます。

## 11.3 range の脱糖

```python
for i in range(3):
    BODY
```

```python
for.ix.0: int = 0
while for.ix.0 < 3:
    i = for.ix.0
    BODY
    for.ix.0 += 1
```

**`range` はリストを作りません。** ただの数え上げに書き換わります。

> `range` は特別扱い（イテレータプロトコルは v1 では作らない）
> — 言語仕様 5.5

`range(a, b)` と `range(a, b, c)` も同じ形です。

| 書き方 | 開始 | 終了 | 増分 |
|---|---|---|---|
| `range(n)` | `0` | `n` | `1` |
| `range(a, b)` | `a` | `b` | `1` |
| `range(a, b, c)` | `a` | `b` | `c` |

### ⚠️ 増分が負のときは条件が逆になる

```python
for i in range(10, 0, -1):    # 10, 9, ..., 1
```

`i < 0` では 1 回も回りません。**`i > 0` でなければなりません。**

つまり**増分の符号で条件が変わります**。実行時に決まる値だと、
`(step > 0 and i < end) or (step < 0 and i > end)` のような
条件を組み立てることになります。

**v1 では「増分は整数リテラル（先頭の `-` は可）に限る」**ことにしました。

```c
    // ⚠️ 増分は整数リテラルだけ（v1 の制限）。
    //    符号が実行時に決まると、条件式が複雑になります。
    //    符号がコンパイル時に分かれば、'<' か '>' を選ぶだけで済みます。
    if (step_node->kind != ND_INT) { /* エラー＋書き方の案内 */ }
```

**🤔 なぜ制限してよいのか**
`range` の増分を変数にする用途はまれで、必要なら `while` で書けます。
**「まれな用途のために実装を複雑にしない」**という判断です
（第5章の「まず動かす、測ってから直す」と同じ姿勢）。

**⚠️ `range(a, b, 0)` は無限ループ**なので、コンパイル時に弾きます。

## 11.4 落とし穴：continue が無限ループになる

### ⚠️ 素朴な脱糖は壊れます

```python
for i in range(5):
    if i == 2:
        continue
    print(i)
```

素朴に「本体の最後に増分を置く」と、こうなります。

```
while.cond.0:               ← continue の飛び先（第7章）
    ...
while.body.0:
    if i == 2: continue     ← ここから while.cond.0 へ飛ぶ
    print(i)
    for.ix.0 += 1           ← ★ 飛ばされる！
```

**`continue` すると増分が実行されず、`i` が 2 のまま止まります。無限ループです。**

第7章でこう書きました。

> `continue` が `while.body.N` に飛ぶと条件を評価せずに次の反復に入ってしまい、
> 無限ループになります。**第11章で `for` を実装するときは、
> `continue` の飛び先が「増分処理」になるので、また変わります。**

**予告どおりの落とし穴に来ました。**

### ✍️ 解決：増分専用のブロックを作る

```
while.cond.0:
    ...
while.body.0:
    BODY
    br label %for.incr.0
for.incr.0:                 ← ★ continue の飛び先はここ
    for.ix.0 += 1
    br label %while.cond.0
while.end.0:
```

コード生成はこうなります。

```c
static void gen_while(Emitter *e, Node *n) {
    ...
    // ★ 増分があるなら、continue の飛び先は「増分ブロック」。
    //   無ければ従来どおり「条件ブロック」（第7章のまま）。
    char incr_l[32];
    const char *cont_l = cond_l;
    if (n->incr) {
        snprintf(incr_l, sizeof(incr_l), "for.incr.%d", id);
        cont_l = incr_l;
    }

    LoopCtx ctx = {.outer = e->loop, .break_label = end_l, .continue_label = cont_l};
    e->loop = &ctx;

    emit_label(e, body_l);
    gen_stmt(e, n->body);

    if (n->incr) {
        emit_label(e, incr_l);      // ★ 本体から自然に落ちてくる
        gen_stmt(e, n->incr);
    }
    if (!e->terminated) emit_br(e, cond_l);
    ...
}
```

**★ `emit_label()` が「終端していなければ `br` を補う」ので、
本体から増分ブロックへは自動的に繋がります**（第6章で作った関数）。

### 📖 予想が外れたこと

第10章の予告では「**コード生成器は無変更で済むはず**」と書きました。
**外れました。** `continue` の飛び先のために、`gen_while` に 10 行ほど足りませんでした。

**それでも `for` 専用のコード生成は 1 行も書いていません。**
`while` が「増分の枠」を持つようになっただけで、
これは **C の `for(init; cond; incr)` が持っているものと同じ**です。

**★ 「完全な無変更」は無理でも、「概念を 1 つ足すだけ」に抑えられれば成功です。**

## 11.5 隠し変数の名前

脱糖で作る変数（`for.it.0` / `for.ix.0`）には、2 つの要求があります。

| 要求 | 満たし方 |
|---|---|
| 利用者の変数と衝突しない | **`.` を含む名前**にする（識別子として書けない） |
| for がネストしても衝突しない | 構文解析器で**連番**を振る |

```c
// 隠し変数の名前を作る。
//
// ⚠️ '.' を含むので、利用者が書ける識別子とは絶対に衝突しません。
//    ネストしても衝突しないように連番を振ります。
//    （シャドーイング禁止なので、同名だと内側の for がエラーになってしまう）
static char *hidden_name(Parser *p, const char *tag) {
    StrBuf sb;
    sb_init(&sb);
    sb_printf(&sb, "for.%s.%d", tag, p->hidden_counter++);
    return sb_str(&sb);
}
```

**⚠️ 連番が要るのは「シャドーイング禁止」のせいです**（第7章）。
同じ名前を使うと、内側の `for` が
**「外側のスコープの変数を隠しています」**というエラーになります。
**自分で決めた規則に、自分の生成したコードが引っかかる**ところでした。

### 📖 エラー位置をどうするか

脱糖で作ったノードは**ソースコードに対応する場所がありません**。
しかし第1章から「全ノードが `Token *tok` を持つ」と決めています。

**元の `for` 文のトークンを流用します。**

```c
Node *n = new_node(ND_VARDECL, for_tok);   // ★ for のトークンを使い回す
```

こうすると、脱糖で作った部分でエラーが出ても
**`for` の行を指してくれます**。利用者にとっては十分な情報です。

ビルド警告 0 件、ASan/UBSan も全ケースでクリーンです。

### ✅ 4 つの形が全部動く

```python

for i in range(3):       # range(n)      → 0 1 2
for i in range(3, 0, -1):# 負の増分      → 3 2 1

```

**`str` を回せるのは、`len()` と `[]` が `str` にも使えるからです。**
`for` 側には 1 行も特別扱いを書いていません。

### ★ continue の落とし穴を実測する（この章の主役）

```python
for i in range(5):
    if i == 2:
        continue
    print(i)
```

**正しい実装（continue の飛び先 = 増分ブロック）：**

```
0
1
3
4
```

**素朴な実装（continue の飛び先 = 条件ブロック）にすると：**

```bash
$ timeout 3 ./t
$ echo $?
124            ← タイムアウト（無限ループ）
$ wc -l out.txt
0              ← 1 行も出力されない
```

**`i` が 2 のまま増分に到達せず、永久に回り続けます。**
出力が 0 行なのは、`0` と `1` を出した後の `print` がバッファに残ったまま
強制終了されるからです。

第7章でこう予告していました。

> 第11章で `for` を実装するときは、
> `continue` の飛び先が「増分処理」になるので、また変わります。

**予告どおりの落とし穴でした。**

### ✅ 生成される IR

```llvm
if.end.1:
  %t5 = load i64, ptr %i
  call void @pl_print_int(i64 %t5)
  br label %for.incr.0        ← 本体の終わりから増分へ
for.incr.0:                   ← ★ continue の飛び先
  ...
```

`continue` の `br` も `for.incr.0` を指しています。

### ✅ 対象は 1 回だけ評価される

```python
def make() -> list[int]:
    print("called")
    return [1, 2]

def main() -> int:
    for x in make():
        print(x)
```

```
called          ← 1 回だけ
1
2
```

**隠し変数に受けているからです。** 毎回評価していたら `called` が 2 回出ます。

### ✅ 入れ子

```python
for i in range(2):
    for j in range(2):
        print(i * 10 + j)
```

```
0
1
10
11
```

**隠し変数に連番を振っているので衝突しません。**
振らなければ、内側の `for.ix` が外側を隠して
**「外側のスコープの変数を隠しています」**（第7章のシャドーイング禁止）
というエラーになっていました。**自分の規則に自分で引っかかるところでした。**

### ✅ ループ変数は for のスコープに閉じている

```python
for x in [1, 2]:
    print(x)
print(x)        # ← エラー
```

```
error: 未定義の名前 'x' です
```

**脱糖の結果をブロックで包んでいるので、第7章のブロックスコープが
そのまま効いています。** 言語仕様 5.5 の「ループ変数はその for 文のスコープに
自動的に宣言される」どおりです。

### ✅ ループ変数もシャドーイング禁止の対象

```python
x: int = 1
for x in [1, 2]:      # ← エラー
```

```
error: 変数 'x' は外側のスコープの変数を隠しています
```

**第7章の規則が、脱糖で作った宣言にもそのまま適用されます。**
特別扱いを書いていないので当然ですが、**規則が一貫していることの確認**になります。

### ✅ エラー：range の増分

```
error: range の増分が定数ではありません
   |
   = ヒント: 増分は整数リテラルで書いてください（例: range(0, 10, 2)）。変数を使いたい場合は while で書けます
```

```
error: range の増分に 0 は使えません
   |
   = ヒント: 増分が 0 だと無限ループになります
```

**制限を伝えるときは、必ず回避策も書きます**（第3章からの約束）。

### ✅ エラー：回せないもの

```python
for x in 42:
```

```
error: len は 'int' 型を受け取れません
```

**⚠️ このメッセージは、脱糖の結果が漏れています。**
利用者は `len` と書いていません。

理想は「`int` は for で回せません」と出すことですが、
そのためには**脱糖の前に型を知る**必要があります
（構文解析器は型を知りません）。

**既知の課題として記録します。**
`for` 専用の検査を sema に足すか、脱糖を sema に移すかの二択になります。

## 次章：第12章 class（構造体とメソッド）

**達成目標**

```python
class Token:
    kind: int
    text: str

    def show(self) -> None:
        print(str(self.kind) + ":" + self.text)

def main() -> int:
    t: Token = Token(1, "abc")
    t.show()
    return 0
```

**やること**
