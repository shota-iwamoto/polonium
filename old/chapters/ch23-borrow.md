# 第23章 借用（保存・返却の禁止）

> **この章のゴール**
> 「借りたものを、貸してくれた相手より長生きさせない」ことをコンパイラが保証する。
>
> ```bash
> $ cat t.po
> class Node:
>     name: str
>     def init(self, name: str) -> None:
>         self.name = name
> $ ./build/poloniumc t.po -o t
> warning[E-BORROW-3]: 借用した値 'name' をフィールドに保存できません
>   --> t.po:4:21
>    |
>  4 |         self.name = name
>    |                     ^^^^ 保存すると、貸してくれた相手より長生きしてしまいます
>    |
> note: 引数 'name' は借用です（既定）
>   --> t.po:3:20
>    |
>  3 |     def init(self, name: str) -> None:
>    |                    ^^^^
>    |
>    = ヒント: 引数を 'name: own str' にすると、所有権を受け取れます
> ```

第22章は「**移動したものを使うな**」でした。この章は「**借りたものを逃がすな**」です。
仕様 v2 の保証 **S2（use-after-free が無い）** を担当します。

**★ この章が Polonium の設計でいちばん大きな賭けの検証です。**
仕様 §4.4 で「借用は呼び出しより長生きしない」と決めたので、
**Rust のライフタイム注釈（`'a`）とリージョン推論は丸ごと不要**になります。
その代わり、この章の規則を破るコードは**書けなくなります**。
実際に書けなくなるのか、どれくらい不便なのかを、`selfhost/`（6,600 行）で測ります。

## 23.2 借用はどこから生まれるか

Polonium では **`&` も借用束縛も書けません**（決定 D3）。
だから借用が生まれる場所は**関数の引数だけ**です。

```python
def total(xs: list[int]) -> int:    # xs は借用（既定）
def fill(xs: mut list[int]) -> None:  # mut も借用（書き換えてよいだけ）
def take(xs: own list[int]) -> int:   # own は借用ではない（所有権を受け取る）
```

**この単純さが、そのまま実装の単純さになります。**
検査中の関数の仮引数を並べておけば、「借りものか」は根をたどるだけで分かります。

```c
typedef struct BorrowRoot BorrowRoot;
struct BorrowRoot {
    const char *key;  // 仮引数の IR 名（%xs）
    Node *param;      // 宣言（診断の note: と「直し方」に使う）
    bool is_self;     // self か（仕様 §4.5 の例外）
    BorrowRoot *next;
};
```

**⚠️ コピー型（`int` / `bool`）は根に入れません。** そもそも移動しないので、
入れても一度も参照されない情報になります。

## 23.3 借りものの「一部」も借りもの

```c
static BorrowRoot *borrow_root_of(Own *o, Place *p) {
    Place *root = p;
    while (root->base) root = root->base;
    if (root->kind != PL_LOCAL) return NULL;  // グローバルは常に生きている（設計 §5.3）
    for (BorrowRoot *b = o->roots; b; b = b->next)
        if (strcmp(b->key, root->key) == 0) return b;
    return NULL;
}
```

`self.name` も `toks[i]` も、根をたどれば仮引数です。
**「借りたものの一部もまた借りもの」** という規則が、この 4 行に収まります。

```python
def first(xs: list[str]) -> str:
    return xs[0]        # ❌ E-BORROW-4：'xs[…]' は 'xs' の一部
```

**★ グローバル変数は借用の根になりません。** プログラムが終わるまで生きているので、
どこへ保存しても寿命の問題が起きないからです（設計 ownership.md §5.3）。

## 23.4 局所変数への束縛は許す

ここがこの章でいちばん考えたところです。

```python
def width(s: str) -> int:
    t: str = s          # これは許すか？
    return len(t)
```

第22章の規則をそのまま当てはめると「代入は移動」なので、
**借用を移動しようとしている** → エラー、になります。
しかし、それでは `t` に別名を付けることすらできず、あまりに不便です。

**🤔 そもそも危険なのか**

危険なのは「**呼び出しより長生きすること**」でした。
局所変数は呼び出しが終われば消えるので、**長生きしません**。
つまり `t: str = s` は安全です。`t` もまた「借りもの」だと考えればよいだけです。

**★ 決定：局所変数への束縛は許し、その変数も借用として追跡する。**

```c
static void bind_alias(Own *o, Node *target, Node *rhs) {
    ...
    BorrowRoot *b = xmalloc(sizeof(BorrowRoot));
    b->key = target->ir_name;
    b->param = src->param;   // 診断は「元の引数」を指す
    ...
}
```

これが無いと、**名前を変えるだけで検査をすり抜けます**。

```python
    def rename(mut self, s: str) -> None:
        t: str = s
        self.label = t     # ❌ E-BORROW-3（note は 's' を指す）
```

`for x in xs:` の脱糖（`for.it.0 = xs` → `x = for.it.0[i]`）もこの道を通るので、
借りたリストの要素を保存しようとすると、ちゃんと止まります。
**第22章で「隠し変数への代入は借用」と決めた判断が、ここでそのまま効きます。**

## 23.5 逃がしてはいけない 4 か所

```c
typedef enum {
    MV_ASSIGN,   // ys = xs        変数への代入   … 許す（§23.4）
    MV_FIELD,    // self.xs = a    フィールドへ保存 … E-BORROW-3
    MV_APPEND,   // xss.append(a)  コンテナへ保存   … E-BORROW-3
    MV_RETURN,   // return a       返す            … E-BORROW-4
    MV_OWN_ARG,  // take(a)        own 引数へ渡す   … E-BORROW-1
} MoveCtx;
```

第22章の `move_expr` に「どういう文脈で移動しようとしているか」を渡すだけで、
**同じ 1 か所**で 4 種類の診断を出し分けられます。

```c
    BorrowRoot *br = borrow_root_of(o, p);
    if (br) {
        if (ctx != MV_ASSIGN && !(ctx == MV_RETURN && br->is_self))
            report_borrow(o, br, p, n, ctx);
        use_expr(o, f, n);
        return;   // ⚠️ 移動として記録しない
    }
```

**⚠️ 借用は「移動として記録しません」。** 借りものは動いていないからです。
記録してしまうと、この後で使うたびに `E-MOVE-1` が連鎖して出ます。
**1 つの問題は 1 回だけ報告する**、が診断の原則です。

| コード | 意味 |
|---|---|
| `E-BORROW-1` | 借用した値は移動できません（`own` 引数へ渡した） |
| `E-BORROW-3` | 借用した値をフィールド／リストに保存できません |
| `E-BORROW-4` | 借用した値は返せません |

**★ 直し方はいつも同じ**なので、ヒントは機械的に作れます。

```c
    d.hint = diag_fmt("引数を '%s: own %s' にすると、所有権を受け取れます",
                      br->param->name, type_name(br->param->type));
```

## 23.6 例外は `self` だけ

```python
class Lexer:
    src: str
    def source(self) -> str:
        return self.src        # ✅ 許す（仕様 §4.5）
```

メソッドが自分のフィールドを返すのは、実質的に「自分の一部を貸す」ことです。
これを禁止すると、**クラスからフィールドを読み出す手段が無くなります**。

```c
        if (ctx != MV_ASSIGN && !(ctx == MV_RETURN && br->is_self))
```

`self` かどうかは「型注釈の無い第 1 引数」で判定します（parser がそう作る。第12章）。

**⚠️ 許すのは「返すこと」だけです。** `other.f = self.name` のように
**別のオブジェクトに保存する**のは `self` 由来でも禁止です。
借りた相手（`self`）より長生きしてしまうからです。

## 23.7 つまずき：`s[i]` は「場所」ではない

実装して `lib/` に流したら、`strings.split` で警告が出ました。

```python
def split(s: str, sep: str) -> list[str]:
    out: list[str] = []
    if m == 0:
        for c in s:
            out.append(c)     # ← 借用した 's' の要素を保存している？
```

**⚠️ これは誤検出でした。** ランタイムを読むと分かります。

```c
char *pl_str_index(const char *s, long long i) {
    ...
    char *p = pl_str_alloc(1);   // ★ 新しく確保している
    p[0] = s[i];
```

`s[i]` は「文字列の中の場所」ではなく、**1 文字の新しい文字列**です。
`list[T]` の要素とは違い、元の文字列を借りているわけではありません。

```c
        case ND_INDEX: {
            // str の添字は「場所」ではない（新しい文字列を作って返す）
            if (n->lhs->type && n->lhs->type->kind == TY_STR) return NULL;
```

**★ 教訓：「同じ構文だから同じ意味」とは限りません。**
`xs[i]` と `s[i]` は構文も型も似ていますが、**片方は借用、片方は生成**です。
仕様（言語仕様 3.1「`str` は不変」）とランタイムの実装を突き合わせて初めて分かりました。
**検査を書くときは、その構文が実行時に何をするのかまで降りて確かめること。**

## 23.8 ライフタイム注釈が要らない理由

Rust なら、この章の規則は**注釈で表現**します。

```rust
fn source<'a>(&'a self) -> &'a str { &self.src }   // Rust
```

```python
def source(self) -> str:                            # Polonium
    return self.src
```

Rust は「どれくらい生きるか」を型に書かせ、コンパイラが制約を解きます
（NLL・リージョン推論）。Polonium は **寿命を 1 種類に固定**しました。

| 借用の作り方 | 有効な範囲 |
|---|---|
| 関数の引数 | その呼び出しの間だけ |
| `for x in xs` の `x` | そのループ本体の 1 反復 |

寿命が 1 種類しか無いので、**比べる必要も、解く制約もありません。**
「逃がしたかどうか」だけを見れば済みます。それがこの章の実装（約 120 行）です。

**⚠️ 代償は「返せない」ことです。** 借用を返したい場面では
`own` を渡すか、添字（`int`）を返すか、`rc[T]`（第28章）を使うことになります。
**その代償が実際にどれくらい重いかは、第26章で `selfhost/` を直すときに分かります。**

## 23.10 第26章の宿題（更新）

| 検査 | `selfhost/` | `lib/` |
|---|---|---|
| `E-MOVE-1`（第22章） | 138 | 0 |
| `E-BORROW-3`（保存） | 76 | 1 |
| `E-BORROW-4`（返却） | 32 | 1 |
| `E-BORROW-1`（移動） | 0 | 0 |
| **合計** | **246** | **2** |

**★ `E-MOVE-1` が 196 件から 138 件に減りました。** 検査を厳しくしたのに減ったのは、
**同じ問題をより早い場所で、より正確な名前で報告するようになった**からです。

```python
    cached: Type | None = elem.opt    # 第22章：ここは通り、後の 'elem' で E-MOVE-1
                                      # 第23章：借用の別名として扱うので、E-MOVE-1 は出ない
```

`E-BORROW-1` が 0 件なのは、`selfhost/` にまだ `own` 引数が 1 つも無いからです。
第26章で `own` を付け始めると、今度はここが増えます。**それが移行が進んだ印になります。**

`lib/` に残った 2 件は、どちらも直し方が既に分かっています。

| 場所 | 内容 | 直し方 |
|---|---|---|
| `lib/strings.po` `replace` | `return s`（借用を返している） | `s: own str` にする |
| `lib/dict.po` `set` | `self.keys_.append(k)` | `k: own str` にする |

**⚠️ この章では直しません。** 直すと呼び出し側に `own` が波及し、
「検査の実装」と「既存コードの移行」が同じ章に混ざります（決定 D10）。

### この章で残した宿題

| 残したもの | いつ |
|---|---|
| 局所コンテナの要素を保存する形（`t = xs[i]` の `xs` が局所変数） | 第25章（`pop()` と同時） |
| 可変借用と他の借用の同時成立（B1）、読み取り専用への書き換え（B3） | 第24章 |
| `rc[T]` による逃げ道 | 第28章 |

## 23.11 まとめと次章の予告

この章でやったこと：

- 借用の根（仮引数）を並べ、**根をたどるだけ**で「借りものか」を判定した
- **局所変数への束縛は許し**、その変数も借用として追跡した（`bind_alias`）
- 逃がす 4 か所（フィールド・コンテナ・戻り値・`own` 引数）を `MoveCtx` で出し分けた
- 例外は `self` のフィールドを**返す**ときだけにした（仕様 §4.5）
- `s[i]` が場所ではないことをランタイムまで降りて確かめた
- **ライフタイム注釈なしで S2（use-after-free の排除）を成立させた**

次章（第24章）は**可変性**です。`mut` を書いていない借用を書き換えていないか（B3）、
1 つの呼び出しで同じ場所を可変借用と別の借用に渡していないか（B1）を見ます。
B1 の実体は**第22章で作った `place_overlaps` の二重ループ**だけです
（[design/ownership.md §5.1](../../docs/design/ownership.md)）。
