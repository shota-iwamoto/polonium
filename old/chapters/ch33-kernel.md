## 33.1 割り込みに必要な 3 つ

RISC-V のマシンモードで、割り込みを受けるのに要るのは 3 つだけです。

| # | やること | 使う CSR / 装置 |
|---|---|---|
| ① | 割り込みの**入口**を登録する | `mtvec` |
| ② | **どの割り込み**を受けるか決める | `mie`（タイマは bit 7 = MTIE） |
| ③ | 割り込みを**許可**する | `mstatus`（bit 3 = MIE） |

タイマは CLINT という装置が持っています。

| 番地 | 意味 |
|---|---|
| `0x200BFF8` | `mtime`（いま何 tick か。10MHz） |
| `0x2004000` | `mtimecmp`（**この時刻になったら割り込む**） |

## 33.2 CSR に触る — `asm` 系の組み込み

CSR（制御レジスタ）はメモリではないので、`poke64` では触れません。
**命令そのもの**が要ります。そこで第30章の低レベル組み込みに 3 つ足しました。

| 組み込み | 用途 | 生成される IR |
|---|---|---|
| `asm(text)` | 命令を並べるだけ | `call void asm sideeffect "…", ""()` |
| `asm_in(text, v)` | 値を 1 つ渡す（`%0`） | `… "r"(i64 %v)` |
| `asm_out(text) -> int` | 値を 1 つ受け取る（`%0`） | `… "=r"()` |

```python
    unsafe:
        asm_in("csrs mie, %0", 128)   # MTIE（bit 7）を立てる
        asm("csrsi mstatus, 8")        # MIE（bit 3）を立てる＝割り込みを許可
        cause = asm_out("csrr %0, mcause")
```

**★ `sideeffect` を必ず付けます。** 付けないと、
「値を返さないのだから消してよい」と最適化に判断され、`csrw` も `wfi` も消えます。

**⚠️ 命令は文字列リテラルでなければなりません**（実行時に組み立てられては困る）。
sema がそれを確かめます。

## 33.3 入口はアセンブリでなければ書けない

割り込みは「関数の途中」に割り込んできます。つまり
**壊してよいレジスタが 1 つもありません**。

```asm
trap_entry:
    addi sp, sp, -128
    sd ra,   0(sp)
    sd t0,   8(sp)
    ...
    call kernel.trap          # ★ 中身は Polonium で書く
    ...
    ld ra,   0(sp)
    addi sp, sp, 128
    mret                      # 割り込まれた場所へ戻る
```

呼び出し規約で「呼ばれた側が壊してよい」ことになっているレジスタ（caller-saved）を
全部退避してから、Polonium の関数を呼びます。

**★ 第32章の `_start` と同じ理由です。**
「言語がレジスタの使い方を決めてしまう」ので、レジスタそのものを扱う場所は
言語の外に出すしかありません。**逆に言えば、外に出すのはここだけです。**

## 33.4 ハンドラを Polonium で書く

```python
ticks: int = 0

def trap() -> None:
    cause: int = 0
    unsafe:
        cause = asm_out("csrr %0, mcause")

    # 最上位ビットが立っていれば割り込み（＝符号付きで見ると負）。下位が 7 ならタイマ。
    if cause < 0 and (cause & 15) == 7:
        ticks = ticks + 1
        print("tick " + str(ticks))
        timer_next(TICK_INTERVAL)
        return

    print("未知の割り込み: " + str(cause))
```

**★ 割り込みハンドラの中で `print` が使えます。**
第31章のフックのおかげで、`print` → `pl_hook_write` → UART と繋がっているからです。

**⚠️ `cause < 0` で「割り込みかどうか」を見ています。**
`mcause` は最上位ビットが「割り込みか例外か」の印なので、
64 ビット符号付き整数として読むと**割り込みは必ず負**になります。
`int` が符号付きの 2 の補数だと決めてある（言語仕様 4.1）ので、これで足ります。

## 33.5 タイマは「次」を自分で決める

```python
def timer_next(delta: int) -> None:
    unsafe:
        now: int = peek64(ptr_at(MTIME), 0)
        poke64(ptr_at(MTIMECMP), 0, now + delta)
```

**⚠️ これを毎回やらないと、割り込みは 1 回しか来ません。**
`mtimecmp` は「この時刻になったら 1 回割り込む」という約束なので、
ハンドラの中で次の時刻を入れ直すのが仕事です。入れ忘れると、
**同じ割り込みが延々と再発します**（`mtime >= mtimecmp` のままなので）。

`peek64` / `poke64` は第30章でもう作ってあります。**装置のレジスタも
ただのメモリ番地**なので、新しい道具は要りませんでした。

## 33.6 キーボード（UART の受信）

```python
def uart_getc() -> int:
    unsafe:
        lsr: int = peek8(ptr_at(UART_BASE + 5), 0)   # 状態レジスタ
        if (lsr & 1) == 1:                            # bit 0 = 受信データあり
            return peek8(ptr_at(UART_BASE), 0)
    return -1
```

割り込みではなく**ポーリング**（来ていれば読む）にしました。
入力が無ければ何も起きないので、**自動テストでも結果が決まります**。

```python
        c: int = uart_getc()
        if c >= 0:
            print("入力: " + chr(c))
```

## 33.7 つまずき：`%0` は IR では `$0`

最初の実装はアセンブラのエラーで落ちました。

```
<inline asm>:1:8: error: expected '%' relocation specifier
```

**⚠️ C で書く `%0`（オペランド）は、LLVM IR では `$0` です。**
`%` は IR ではレジスタの印であり、RISC-V では `%hi(sym)` のような
**再配置指定**にも使われるので、そのまま渡すと別物として読まれます。

利用者には C と同じ `%0` で書いてもらい、**codegen が `$0` に直します**。

```c
            if (*c == '%' && c[1] >= '0' && c[1] <= '9') {
                sb_printf(&asmbuf, "$%c", c[1]);
```

**★ 「利用者が知っている書き方」と「機械が求める書き方」が違うとき、
翻訳するのはコンパイラの仕事です。** 第11章の `for` の脱糖と同じ立場です。

## 33.8 動作確認

```bash
$ make qemu-test
  ok    Polonium kernel on RISC-V (virt)
  ok    1 から 10 までの合計: 55
  ok    v2 の言葉: raises
  ok    tick 1
  ok    tick 3
  ok    3 回割り込みが来ました
  ok    halt
★ ベアメタルの RISC-V で Polonium のカーネルが動きました
```

**★ `tick 1` と `tick 3` の両方を見ているのが要点です。**
1 回目だけなら「たまたま 1 回来た」で説明できますが、3 回来たということは
**`mtimecmp` の入れ直しが効いている**——つまり割り込みの往復が
ちゃんと回っているということです。

## 33.9 まとめ — ここまでで何ができたのか

この章でやったこと：

- `asm` / `asm_in` / `asm_out` で CSR に触れるようにした
- 割り込みの入口（レジスタ退避）をアセンブリで書き、**中身は Polonium** にした
- タイマ割り込みを受け、`print` で数え、`mtimecmp` を入れ直した
- UART の受信をポーリングで読んだ
- 出力で判定する自動テストにした

**ここまでで、この言語は次のことができます。**

| | |
|---|---|
| 書ける | Python の見た目・静的型・所有権による安全性・エラー処理 |
| 自分を作れる | セルフホスト（stage2 == stage3 の不動点） |
| 壊れにくい | 移動・借用・可変性の検査、自動解放、`make drop-asan` |
| 逃げ道がある | `rc[T]`（共有）・`unsafe:`（低レベル）・`extern`（C との橋） |
| **OS になれる** | **libc 無しで動き、割り込みを受け取れる** |

**★ 「Python の書きやすさのまま、Rust の安全性を手に入れ、OS を書く」**——
