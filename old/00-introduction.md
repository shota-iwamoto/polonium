# 第0章 はじめに — 何を作るのか、どう作るのか

## 0.1 ゴール

作るものは 3 つです。

1. **Polonium という言語** … Python 風の文法、ただし静的型付け・コンパイル方式。
2. **poloniumc というコンパイラ** … C 言語で書く。Polonium のソースを LLVM IR に変換する。
3. **セルフホスト** … Polonium 自身で書いた Polonium コンパイラが、自分自身をコンパイルできる状態。

最終的に、こうなります。

```
$ cat hello.po
def main() -> int:
    print("hello, polonium")
    return 0

$ poloniumc hello.po -o hello
$ ./hello
hello, polonium
```

そして最終章では、**Polonium で書かれたコンパイラ**が、
**Polonium で書かれたコンパイラのソースコード**をコンパイルして、
**まったく同じバイナリ**を吐き出します。これがセルフホストです。

---

## 0.2 「コンパイラ」とは結局なにをする道具か

コンパイラは、**テキストを別のテキスト（or バイナリ）に翻訳するプログラム**です。
それ以上でもそれ以下でもありません。

入力はただの文字列です。

```
"return 1 + 2"
```

出力もただの文字列です（LLVM IR）。

```llvm
define i32 @main() {
entry:
  %t0 = add i64 1, 2
  %t1 = trunc i64 %t0 to i32
  ret i32 %t1
}
```

この翻訳を一気にやるのは無理なので、**小さな変換の連鎖**に分解します。
これがコンパイラの基本構造です。

```
ソースコード（文字列）
    │
    │  ① 字句解析 (Lexer / Tokenizer)
    ▼
トークン列   [RETURN] [INT:1] [PLUS] [INT:2] [NEWLINE] [EOF]
    │
    │  ② 構文解析 (Parser)
    ▼
抽象構文木 (AST)        Return
                          └─ BinOp(+)
                              ├─ IntLit(1)
                              └─ IntLit(2)
    │
    │  ③ 意味解析・型検査 (Semantic Analysis / Type Checker)
    ▼
型注釈つき AST          Return
                          └─ BinOp(+) : int
                              ├─ IntLit(1) : int
                              └─ IntLit(2) : int
    │
    │  ④ コード生成 (Code Generator)
    ▼
LLVM IR（文字列）
    │
    │  ⑤ LLVM（clang / llc）に丸投げ
    ▼
機械語・実行ファイル
```

**⑤を自分で書かないのがこの本の最大のポイントです。**
機械語生成・レジスタ割り当て・最適化は LLVM がやってくれます。
私たちは ①〜④ に集中します。

### 各段階が答える質問

| 段階 | 答える質問 | 例：エラーになるもの |
|---|---|---|
| ① 字句解析 | 「この文字の並びは、どんな**単語**に分けられるか？」 | `1 @@ 2` → `@@` なんて単語はない |
| ② 構文解析 | 「その単語の並びは、**文として成り立つ**か？」 | `1 + + ` → 式が途中で終わっている |
| ③ 型検査 | 「成り立つ文だが、**意味は通る**か？」 | `1 + "a"` → int と str は足せない |
| ④ コード生成 | 「意味の通る木を、**どう命令列にする**か？」 | （エラーは出ないのが理想） |

## 0.3 なぜ LLVM を使うのか

自分で x86-64 の機械語を吐くこともできます（それも良い勉強です）。
しかし今回 LLVM を選ぶ理由は 4 つあります。

1. **移植性** … Intel Mac でも Apple Silicon でも Linux でも同じ IR が動く。
2. **最適化が無料** … `-O2` を付けるだけで、素朴な生成コードが劇的に速くなる。
   特に後述の「全部 alloca 方式」は、LLVM の `mem2reg` が掃除してくれる前提の設計です。
3. **IR が読める** … LLVM IR はテキストです。生成結果を目で読んで学べます。
4. **デバッグしやすい** … 生成した `.ll` を `lli` で直接実行したり、`opt` で検証できます。

### 今回の方式：LLVM IR **テキスト**を出力する

LLVM の使い方には 2 通りあります。

| 方式 | 説明 | 採用 |
|---|---|---|
| **A. IR テキストを `printf` で出力** | `.ll` ファイルを文字列として書き出し、`clang foo.ll -o foo` に渡す | ✅ **こちら** |
| B. LLVM C API にリンク | `LLVMBuildAdd(...)` などの関数で IR を組み立てる | ❌ |

**🤔 なぜ A なのか？**

- コンパイラ側のコードが `fprintf` だけになり、**圧倒的に読みやすい**。
- 生成物が人間可読なので、**バグの原因がすぐわかる**。
- そして決定的な理由 → **セルフホストが現実的になる**。
  B 方式だと、Polonium から LLVM の C API を呼ぶ FFI 機構を言語に実装しなければなりません。
  A 方式なら、Polonium 側に必要なのは「**文字列を組み立てて print する**」機能だけです。

代償は「IR の文法ミスが実行時（clang 実行時）にしかわからない」ことですが、
これは `clang` のエラーメッセージが十分親切なので実用上問題になりません。

## 0.4 なぜ静的型付けなのか

Python 風の見た目にしつつ、**型は静的に決める**方針です。

```python
def add(a: int, b: int) -> int:      # 型注釈は必須
    return a + b

def main() -> int:
    x: int = add(1, 2)               # 変数宣言に型を書く
    print(x)
    return 0
```

**🤔 なぜ？**

1. **コンパイル時に型が決まれば、実行時の型タグが不要になる**。
   動的型付けだと、`a + b` を実行するたびに「a は int か？ str か？」を実行時に調べる必要があり、
   すべての値を「型タグ + データ」のボックスに包む必要があります。
   静的型なら、`add i64` という 1 命令に落ちます。
2. **型検査という学習項目が入る**。これはコンパイラ作成の中核スキルの 1 つです。
3. **自分自身をコンパイルするとき、型情報が実装の安全網になる**。

Python との非互換は割り切ります。Polonium は「Python に似ているが Python ではない」言語です。
互換性の詳細は [spec/language-spec.md](../docs/spec/language-spec.md) の「Python との差異」節にまとめます。

## 0.5 開発の進め方（インクリメンタル開発）

**絶対に守るルール：どの時点でも、コンパイラは動く状態を保つ。**

「全部書いてから動かす」は必ず失敗します。代わりに、こう進めます。

```
第1章:  整数を返すだけ                 → ./a.out; echo $?  →  42
第2章:  1+2*3 が計算できる             → 7
第3章:  エラーが親切に出る
第4章:  複数行・インデントが読める
第5章:  変数が使える
 ...
第20章: 自分自身をコンパイルできる
```

各章の作業サイクルは常に同じです。

```
1. 章のドキュメントを読む（設計を理解する）
2. テストケースを先に書く（何が動けば完成かを決める）
3. Lexer を直す  →  make test（まだ落ちる）
4. Parser を直す →  make test（まだ落ちる）
5. Codegen を直す →  make test（通る！）
6. dev-log.md に記録する
7. git commit する
```

**⚠️ 落とし穴**：先の章の機能を前借りして実装しないこと。
「どうせ後で文字列も要るから今のうちに」は、動かないコードの山を作る最短ルートです。

## 0.7 前提知識

必要なもの：

- **C 言語の基本** … ポインタ、`struct`、`malloc`、`switch`、関数ポインタ（後半で少し）。
  「ポインタが完全に理解できていない」程度なら問題ありません。都度解説します。
- **ターミナルの基本操作** … `cd`、`ls`、`make`。

不要なもの：

- コンパイラ理論の授業（この教材で説明します）
- LLVM の知識（[reference/llvm-ir-primer.md](reference/llvm-ir-primer.md) で 0 から説明します）
- アセンブリの知識（LLVM に任せるので不要）
