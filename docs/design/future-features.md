# 未実装機能の設計

[roadmap.md](../roadmap.md) で「これから入れる」とした機能を、**実装できる粒度まで**
決めたものです。仕様が固まったものは [spec/](../spec/) に移します。

各項目は次の順で書きます。

1. **何が困っているか**（いまのコードでの実例）
2. **どう書けるようにするか**（構文）
3. **どう実装するか**（どのパスに何を足すか）
4. **決めたこと**と**捨てたこと**

> **前提** — 2 つの実装（C 版 `src/` と Polonium 版 `selfhost/`）に**同じものを入れ**、
> 同じ IR を出さなければなりません。片方だけ直すとセルフホストの検証が壊れます。
> 実装の重さを見積もるときは、常に**この 2 倍**で考えてください。

## 1. ジェネリクス

### 何が困っているか

標準ライブラリの `dict` は、**鍵が `str`・値が `int` に固定**されています。

```python
class Dict:
    def get(self, k: str) -> int: ...
    def set(mut self, k: own str, v: int) -> None: ...
```

`str → Symbol` の表が欲しいときは書けません。実際にコンパイラ自身が、
この制約のせいで「値には `list` の添字を入れる」という回り道をしています。

```python
table: list[Symbol] = []
syms: dict.Dict = dict.Dict()
syms.set("x", len(table) - 1)      # 添字を覚えておく
```

これは**ジェネリクスが無いことの直接の帰結**です。

### どう書けるようにするか

```python
class Dict[K, V]:
    def get(self, k: K) -> V: ...
    def set(mut self, k: own K, v: own V) -> None: ...

def first[T](xs: list[T]) -> T | None:
    if len(xs) == 0:
        return None
    return xs[0]

d: Dict[str, Symbol] = Dict()
```

### どう実装するか

**単相化（monomorphization）を採る。** 使われた型の組み合わせごとに実体を作ります。

```
Dict[str, int]    → @Dict.str.int.get
Dict[str, Symbol] → @Dict.str.Symbol.get
```

| パス | 足すこと |
|---|---|
| 字句 | 変更なし |
| 構文 | `class C[K, V]` と `def f[T]` の型引数リスト。型参照 `C[A, B]` |
| 型 | `TY_TYPEVAR`（型変数）と、型引数を持つ `TY_CLASS` |
| 意味解析 | 型引数の束縛と単一化。**呼び出し側から型を推論する**（`Dict()` の型引数は左辺から） |
| 単相化 | 意味解析の後に新しいパスを 1 つ。使われた組み合わせを集め、AST を複製して型変数を置換 |
| コード生成 | 変更なし（単相化後は型が全部確定しているため） |

**単相化を選ぶ理由。** 型消去（1 つの実体で済ませる）だと、`int` と `str` で
値の大きさと解放の要否が違うため、ボックス化が要ります。GC を持たない方針と
噛み合いません。単相化ならコード生成器に一切手を入れずに済みます。

### 決めたこと / 捨てたこと

| | |
|---|---|
| ✅ 採る | 単相化。型引数は `[]`。型引数の推論は「左辺の型から」だけ |
| ✗ 捨てる | 型制約（`T: Comparable`）。**インタフェースが入ってから**考える |
| ✗ 捨てる | 可変長の型引数、既定の型引数 |
| ⚠️ 注意 | 再帰的な型（`class Node[T]` が `Node[T]` を持つ）で単相化が止まらなくなる。
深さに上限を設けて診断を出す |

## 2. インタフェース

### 何が困っているか

「`drop` を持つ」「文字列にできる」といった**共通の振る舞い**をまとめられません。
継承が無いので、同じメソッドを持つ 2 つのクラスを同じ型として扱えません。

### どう書けるようにするか

```python
interface Show:
    def show(self) -> str

class Point(Show):
    x: int
    y: int
    def show(self) -> str:
        return "(" + str(self.x) + ")"

def print_all(xs: list[Show]) -> None:
    for s in xs:
        print(s.show())
```

### どう実装するか

**vtable 方式。** インタフェース型の値は「実体へのポインタ＋メソッド表へのポインタ」の
2 語（ファットポインタ）で表します。

```llvm
%pl.iface = type { ptr, ptr }   ; { 実体, vtable }
```

| パス | 足すこと |
|---|---|
| 構文 | `interface` 宣言、`class C(I1, I2)` の実装宣言 |
| 型 | `TY_IFACE` |
| 意味解析 | クラスが必要なメソッドを全部持つかの検査。クラス型 → インタフェース型の代入互換 |
| コード生成 | クラスごとに vtable を定数で出す。メソッド呼び出しを vtable 経由の間接呼び出しに |

**所有権との関係** — インタフェース型の値は所有型として扱います（中身の解放が要るため）。
vtable に `drop` の欄を置き、`--drop` のときはそこを呼びます。

### 決めたこと / 捨てたこと

| | |
|---|---|
| ✅ 採る | インタフェース（振る舞いだけ）。**実装の継承は入れない** |
| ✗ 捨てる | クラスの継承。フィールドのレイアウトが複雑になり、得るものが少ない |
| ✗ 捨てる | 既定実装つきメソッド（Rust のトレイトの既定実装）。最初は無しで様子を見る |

## 3. 関数型とクロージャ

### 何が困っているか

**関数を値として渡せません。** ソートの比較関数すら渡せないので、
標準ライブラリに `sort` が置けません。

### どう書けるようにするか

```python
def apply(f: fn(int) -> int, x: int) -> int:
    return f(x)

def double(x: int) -> int:
    return x * 2

def main() -> int:
    print(apply(double, 21))         # 関数を渡す

    k: int = 10
    add_k: fn(int) -> int = |x| x + k    # クロージャ（k を捕まえる）
    print(apply(add_k, 1))
    return 0
```

### どう実装するか

段階的に入れます。**① 関数ポインタだけ**なら小さく、**② 捕獲つき**は所有権と絡みます。

**① 関数ポインタ**（捕獲なし）

| パス | 足すこと |
|---|---|
| 構文 | 型 `fn(A, B) -> C`。関数名を値として書けるようにする |
| 型 | `TY_FN`（引数の型の並びと戻り型） |
| コード生成 | LLVM の関数ポインタそのまま。呼び出しは間接呼び出し |

**② クロージャ**（捕獲あり）

捕獲した変数を持つ構造体を作り、`{ 関数ポインタ, 環境 }` の 2 語で表します。
インタフェースと同じファットポインタです。

**⚠️ ここで所有権の問題が出ます。** 捕獲した変数の寿命がクロージャより短いと
壊れたポインタになります。**最初は「所有権を移す捕獲（move）だけ」**を許します。
借用の捕獲は、寿命の検査を入れてから。

### 決めたこと / 捨てたこと

| | |
|---|---|
| ✅ 採る | まず ①（関数ポインタ）だけ入れて `sort` を書けるようにする |
| ✅ 採る | ② は捕獲を**所有権の移動だけ**に限る |
| ✗ 捨てる | 借用の捕獲（寿命の検査が要る）。②の後 |
| ✗ 捨てる | 可変長引数の関数型 |

## 4. スライスと `list` のメソッド

いちばん小さく、いちばん効くところです。**ジェネリクスの前に入れられます。**

```python
xs[1:3]        # list[T] → list[T]（複製）
s[1:3]         # str → str（複製）

xs.pop()       # 末尾を取り出す
xs.insert(i, v)
xs.remove(i)
xs.index(v)    # 見つからなければ -1
xs.reverse()
```

| パス | 足すこと |
|---|---|
| 構文 | 添字の中に `:` を許す（`ND_SLICE`） |
| 意味解析 | メソッド名の表を `append` 以外にも広げる |
| ランタイム | `pl_list_pop` / `pl_list_insert` / `pl_list_slice` / `pl_str_slice` |

**⚠️ 所有権** — `xs[1:3]` は**新しい list を作る**（借用ではない）と決めます。
借用のスライスは寿命の検査が要るためです。

## 5. `in` 演算子

```python
if x in xs:        # list[T]  … 線形探索
if sub in s:       # str      … 部分文字列
if k in d:         # dict     … 鍵の存在
```

構文は `ND_BINOP` に `OP_IN` / `OP_NOTIN` を足すだけ。
意味解析で右辺の型を見て、対応するランタイム関数（または `dict.has`）に落とします。

---

## 6. 三項演算子

```python
x: int = a if cond else b
```

**脱糖で済みます。** 短絡評価（`and` / `or`）と同じく、alloca に置いて分岐で書き分ける形に
落とせば、コード生成器の既存の仕組みがそのまま使えます（規約 R3）。

---

## 7. 文字列の書式化

```python
name: str = "polonium"
print(f"hello, {name} ({len(name)})")
```

**字句解析で脱糖します。** `f"..."` を `"hello, " + name + " (" + str(len(name)) + ")"`
という AST に組み立ててしまえば、後段は何も知らずに済みます。

**⚠️ 埋め込む式は `str` に変換できる型だけ**に限ります（`str()` の
オーバーロードが無い型は書けない）。書式指定（`{x:>8}`）は入れません。

## 8. 標準入力 — **実装済み**（0.2.0）

`io.read_line()` / `io.read_all()` として入りました。仕様は
[spec/stdlib.md](../spec/stdlib.md#標準入力) を参照してください。

**決めたとおり `runtime/hosted.c` に置き、`core.c` の 4 フックは増やしませんでした。**
ベアメタルには標準入力が無く、カーネル側に「使わないのに実装しなければならない
フック」を強いることになるためです。

## 9. 見送るもの

「入れない」と決めたものです。理由も残します。

| 機能 | 見送る理由 |
|---|---|
| クラスの継承 | フィールドのレイアウトと仮想呼び出しが複雑になる。インタフェースで足りる |
| 例外（アンワインド） | ランタイムに巻き戻しの機構が要る。ベアメタルで動かせなくなる |
| GC | 所有権と `rc[T]` で足りるようにするのが、この言語の主張そのもの |
| 動的な属性追加 | 静的レイアウトを壊す |
| 演算子の暗黙変換 | `int` と `float` すら混ぜない方針（言語仕様 3.5） |
| 比較の連鎖 `a < b < c` | 読み間違いを生む。`and` で書く |
| truthiness | `if xs:` は `if len(xs) > 0:` と書く |
