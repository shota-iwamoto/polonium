# Polonium 言語仕様書 v1

> このドキュメントは「Polonium とは何か」の**唯一の正解**です。
> 実装で迷ったらここに戻ります。仕様を変えたいときは、コードより先にここを書き換えます。
>
> 各機能の右側に、それが実装される章を書いてあります（例：`[ch7]`）。

---

## 1. 設計方針

Polonium は次の 4 つの原則で設計します。

1. **見た目は Python** — インデントでブロック、`def`、`:`、`#` コメント。Python を書ける人が読める。
2. **型は静的** — すべての変数・引数・戻り値の型がコンパイル時に確定する。型注釈は必須。
3. **実行時型情報は持たない** — 値は「型タグ付きボックス」ではなく生のマシン値。`int` は `i64` そのもの。
4. **自分自身を書けること** — 言語機能の採否は「コンパイラを書くのに必要か」で判断する。
   必要なら入れる、不要なら入れない。「Python にあるから入れる」は採用理由にならない。

## 2. 字句 (Lexical Structure)

### 2.1 ソースファイル

- エンコーディング: **UTF-8**
- 拡張子: `.po`
- 改行: `\n`（`\r\n` は読み込み時に `\n` に正規化する）
- ファイル末尾に改行がなくてもよい

### 2.2 コメント `[ch1]`

`#` から行末まで。ブロックコメントはありません。

```python
# これはコメント
x: int = 1  # 行末コメントも可
```

### 2.3 論理行と物理行 `[ch4]`

- **物理行** = ファイル中の改行で区切られた 1 行
- **論理行** = 文法上の 1 行

括弧 `(` `[` `{` の中では改行が無視され、複数の物理行が 1 論理行になります。

```python
x: int = (1 +
          2)          # 1 論理行
```

行末のバックスラッシュによる継続（`\`）は **v1 では未対応**です。

### 2.4 インデント `[ch4]`

Python と同じオフサイドルールを使います。

- インデントは **半角スペースのみ**。**タブは字句エラー**とする。
- 推奨インデント幅は 4 だが、言語仕様上は「同じブロック内で一貫していること」だけを要求する。
- 論理行の先頭でインデント幅が
  - 増えたら → `INDENT` トークンを 1 個生成
  - 減ったら → スタックを巻き戻し、戻した段数だけ `DEDENT` トークンを生成
  - 減った先の値がスタックに存在しない → **インデントエラー**
- 空行および `#` だけの行は、インデント計算の対象外（完全に無視する）

**🤔 なぜタブを禁止するのか**
タブ幅の解釈（4 か 8 か）で意味が変わるコードが書けてしまうのは、言語として欠陥です。
Python は歴史的経緯で許容していますが、新しい言語なら禁止すべきです。実装も単純になります。

### 2.5 キーワード

v1 で予約されている語（未使用のものも予約しておき、将来の追加に備えます）。

```
and      as       break    class    continue def      elif     else
extern   False    for      if       import   in       is       None
not      or       pass     return   True     while
```

v2 で追加した語（[safety-spec.md](safety-spec.md)。`own` / `mut` は第21章から使えます）:

```
own      mut      raises   unsafe   pragma
```

将来のために予約（使うとエラー）:

```
assert   const    del      except   finally  from     global   lambda
match    nonlocal raise    try      with     yield
```

⚠️ `del` / `try` / `except` / `with` は v1 の時点で予約済みです。
v2 ではこれらに意味が付きます（`del` は第25章、`try` / `except` は第27章、`with` は第28章）。

### 2.6 識別子

- 1 文字目: `A-Z` `a-z` `_`
- 2 文字目以降: `A-Z` `a-z` `0-9` `_`
- 大文字小文字を区別する
- 非 ASCII 文字は **v1 では識別子に使えない**（実装を単純にするため）

### 2.7 リテラル

| 種類 | 例 | 型 | 章 |
|---|---|---|---|
| 10進整数 | `0` `42` `1_000_000` | `int` | ch1 |
| 16進整数 | `0xFF` `0xff` | `int` | ch2 |
| 2進整数 | `0b1010` | `int` | ch2 |
| 8進整数 | `0o755` | `int` | ch2 |
| 浮動小数点 | `3.14` `1e-3` `2.0` | `float` | ch9 |
| 真偽値 | `True` `False` | `bool` | ch6 |
| 文字列 | `"hello"` `'hi'` | `str` | ch9 |
| None | `None` | `None` | ch12 |

- `_` は数値リテラル中の桁区切りとして使え、値には影響しない（`1_000` == `1000`）。
- 整数リテラルが `int` の範囲（64bit 符号付き）を超えたら**コンパイルエラー**。
- 文字列は `"` または `'` で囲む。三重引用符は v1 未対応。

#### 文字列エスケープ `[ch9]`

| 記法 | 意味 |
|---|---|
| `\n` | 改行 (0x0A) |
| `\t` | タブ (0x09) |
| `\r` | 復帰 (0x0D) |
| `\0` | NUL (0x00) — ⚠️ 3.4 節の注意を参照 |
| `\\` | バックスラッシュ |
| `\"` | 二重引用符 |
| `\'` | 単一引用符 |
| `\xHH` | 16進 1 バイト |

### 2.8 演算子・区切り記号

```
+   -   *   /   //  %   **
==  !=  <   <=  >   >=
and or  not
&   |   ^   ~   <<  >>
=   +=  -=  *=  //=  %=
(   )   [   ]   {   }
,   :   .   ->
```

## 3. 型 (Types)

詳細な型付け規則は [type-system.md](type-system.md) にあります。ここでは一覧のみ。

### 3.1 プリミティブ型

| Polonium 型 | LLVM 表現 | サイズ | 説明 | 章 |
|---|---|---|---|---|
| `int` | `i64` | 8 | 64bit 符号付き整数。オーバーフローは 2 の補数でラップ | ch1 |
| `bool` | `i1`（メモリ上は `i8`） | 1 | `True` / `False` | ch6 |
| `float` | `double` | 8 | IEEE 754 倍精度 | ch9 |
| `str` | `ptr` | 8 | NUL 終端 UTF-8 バイト列へのポインタ。**不変** | ch9 |
| `None` | `void` | 0 | 値を持たない型。戻り値なし関数の戻り型 | ch8 |

### 3.2 複合型

| 型 | LLVM 表現 | 説明 | 章 |
|---|---|---|---|
| `list[T]` | `ptr`（`{ptr data, i64 len, i64 cap}` を指す） | 可変長配列。参照セマンティクス | ch10 |
| `dict[K, V]` | `ptr` | ハッシュマップ。標準ライブラリで実装 | ch14 |
| ユーザー定義 `class` | `ptr`（構造体を指す） | 参照セマンティクス | ch12 |
| `T \| None` | `ptr`（`null` 可） | Nullable。`class` 型と `str` にのみ適用可 | ch12 |

### 3.3 型注釈が必須な場所

```python
def f(a: int, b: str) -> bool:      # 引数と戻り値：必須
    x: int = 0                       # ローカル変数の初期宣言：必須
    x = 1                            # 再代入：不要（宣言時の型を使う）
    return True

g: int = 10                          # グローバル変数：必須

class Token:
    kind: int                        # フィールド：必須
    text: str
```

**🤔 なぜ型推論を入れないのか**
`x = 0` から `int` を推論するのは簡単ですが、
「型注釈を必ず書く」ルールにすると **型検査器が「調べる」だけになり「推論する」必要がなくなる**ため、
実装が劇的に単純になります。第5章で型検査を書くときに、この判断の効果を実感します。
（v2 以降で局所的な型推論を追加する余地は残します。）

### 3.4 `str` の表現について（重要な設計判断）

v1 の `str` は **C と同じ NUL 終端バイト列**です。

```
  s: str = "abc"
        ↓
  ptr ──→ [ 'a' ][ 'b' ][ 'c' ][ 0x00 ]
```

| メリット | デメリット |
|---|---|
| C の関数（`strlen`, `printf`, `fopen`）にそのまま渡せる | `len(s)` が O(n) |
| ランタイムが極小で済む | 文字列中に NUL を含められない |
| 実装が単純で、初学者が中身を追える | 部分文字列を取るたびにコピーが必要 |

**⚠️ 落とし穴**：`"a\0b"` と書いた文字列の `len()` は 1 になります。
これは仕様上の既知の制限です（コンパイラを書く用途では問題になりません）。

`{ptr, len}` 方式（長さを持つ）への移行は第9章で改めて検討し、判断を記録します。

### 3.5 暗黙の型変換はしない

`int` と `float` を混ぜた演算は**コンパイルエラー**です。明示的に変換します。

```python
x: int = 3
y: float = 1.5
z: float = float(x) + y    # OK
w: float = x + y           # ✗ エラー: int と float は加算できません
```

**🤔 なぜ？** 暗黙変換は型検査器に「どちらに合わせるか」の複雑なルール（型昇格）を要求します。
初学者向けの実装としては、エラーにするのが最も明快です。

## 4. 式 (Expressions)

### 4.1 演算子の優先順位

上が**弱い**（後で結合する）、下が**強い**。同じ行の演算子は同順位。

| 順位 | 演算子 | 結合 | 章 |
|---|---|---|---|
| 1 | `or` | 左 | ch6 |
| 2 | `and` | 左 | ch6 |
| 3 | `not x` | 単項 | ch6 |
| 4 | `==` `!=` `<` `<=` `>` `>=` `in` `is` | 左（連鎖は不可） | ch6 |
| 5 | `\|` | 左 | ch2 |
| 6 | `^` | 左 | ch2 |
| 7 | `&` | 左 | ch2 |
| 8 | `<<` `>>` | 左 | ch2 |
| 9 | `+` `-` | 左 | ch2 |
| 10 | `*` `/` `//` `%` | 左 | ch2 |
| 11 | `-x` `+x` `~x` | 単項（右結合） | ch2 |
| 12 | `**` | **右** | ch9 |
| 13 | `f(...)` `x[...]` `x.attr` | 後置（左） | ch10, ch12 |
| 14 | リテラル、識別子、`(...)` | — | ch1 |

**⚠️ Python との差異**：Python は `a < b < c` の**比較連鎖**を許しますが、Polonium v1 では
**構文エラー**にします（`a < b and b < c` と書く）。実装の単純化のためです。

### 4.2 算術演算

| 演算子 | int | float | str | 意味 |
|---|---|---|---|---|
| `+` | ✅ | ✅ | ✅ 連結 | 加算 |
| `-` | ✅ | ✅ | ✗ | 減算 |
| `*` | ✅ | ✅ | ✗ | 乗算 |
| `/` | ✗ | ✅ | ✗ | 真の除算（float のみ） |
| `//` | ✅ | ✗ | ✗ | 切り捨て除算（int のみ） |
| `%` | ✅ | ✗ | ✗ | 剰余 |
| `**` | ✅ | ✅ | ✗ | べき乗（`int ** int` で指数が負なら実行時エラー） |

**⚠️ Python との差異**：`int / int` は **エラー**です。Python では `float` を返しますが、
Polonium は暗黙変換を持たないため、`//`（整数除算）か `float(a)/float(b)` を明示させます。

- `//` と `%` は **C 準拠の切り捨て（truncated）**、つまり LLVM の `sdiv`/`srem` の意味です。
  Python の floor 除算とは負数で結果が異なります。
  | 式 | Python | Polonium |
  |---|---|---|
  | `-7 // 2` | `-4` | `-3` |
  | `-7 % 2` | `1` | `-1` |
  これは既知の非互換です。（`sdiv` 1 命令で済み、実装が単純なため。）
- 0 除算は**実行時エラー**（プログラムを異常終了させる）。

### 4.3 比較演算

すべて `bool` を返します。両辺は**同じ型**でなければなりません。

- `int`, `float`, `bool`: 値の比較
- `str`: **内容**の比較（`==` は `strcmp(a,b)==0`）
- `class` 型: **参照（アドレス）**の比較
- `is` / `is not` `[ch15]`: **`None` との比較にだけ**使える（`x is None` / `x is not None`）
  - 左辺は `T | None` 型でなければならない
  - 一般の同一性比較には使わない（`class` の `==` が既に参照比較のため）

### 4.3.1 nullable と絞り込み `[ch15]`

```python
t: Token | None = find()
if t is not None:
    print(t.kind)      # ★ この中でだけ t は Token
```

- `T | None` にできるのは**参照型**（`str` / `list[T]` / class）だけ
- `T` → `T | None` は代入できる（広げる方向のみ）
- `T | None` のまま `.` で触ることはできない（先に絞り込む）
- 絞り込めるのは**ローカル変数**だけ（グローバル変数・フィールドは対象外）
- 絞り込みは**代入で解除**される（`cur = cur.next` のあとは `T | None` に戻る）
- `if x is None: return` のようなガード節の後ろでも絞り込まれる

### 4.4 論理演算 `[ch6]`

- `and` / `or` は**短絡評価**する。両辺は `bool` 型のみ（`int` を真偽値扱いしない）。
- `not` は `bool` を取り `bool` を返す。
- 結果は `bool`。**Python のように「最後に評価した値」を返さない**（型が一意に決まらないため）。

**⚠️ Python との差異**：`if xs:`（空リストが偽）のような **truthiness は採用しません**。
`if len(xs) > 0:` と明示的に書きます。

### 4.5 関数呼び出し

```python
f(a, b)
```

- 引数の**個数**と**型**が一致しなければコンパイルエラー
- デフォルト引数・キーワード引数・可変長引数は **v1 未対応**
- 評価順は**左から右**

## 5. 文 (Statements)

### 5.1 変数宣言 `[ch5]`

```python
x: int = 0
```

- 初期化式は**必須**（未初期化変数を作らせない）
- 同一スコープでの再宣言はエラー
- 内側のスコープでの同名宣言（シャドーイング）は **v1 では禁止**（混乱を避けるため）

### 5.2 代入 `[ch5]`

```python
x = 1
xs[0] = 1          # ch10
p.field = 1        # ch12
x += 1             # 複合代入 ch5
```

複合代入 `x op= e` は `x = x op e` に脱糖します（左辺は 1 回だけ評価）。

### 5.3 if / elif / else `[ch7]`

```python
if cond:
    ...
elif cond2:
    ...
else:
    ...
```

条件式は **`bool` 型でなければならない**。

### 5.4 while `[ch7]`

```python
while cond:
    ...
```

`while ... else:` は未対応。`break` / `continue` が使えます。

### 5.5 for `[ch11]`

```python
for i in range(10):
    ...
for i in range(2, 10):
    ...
for i in range(0, 10, 2):
    ...
for x in xs:            # xs: list[T] → x: T
    ...
```

- ループ変数は**その for 文のスコープに自動的に宣言される**（型注釈は不要、要素型から決まる）
- ループ変数への代入は許すが、次の反復で上書きされる
- `range` は特別扱い（イテレータプロトコルは v1 では作らない）

### 5.6 return `[ch8]`

```python
return expr
return          # 戻り型が None の関数のみ
```

- 戻り型が `None` 以外の関数は、**すべての実行経路で return しなければならない**（コンパイル時に検査）

### 5.7 pass

何もしない文。空のブロックを書くために使います。

### 5.8 式文

```python
print(x)
obj.method()
```

呼び出し式のみ許可します。`1 + 2` のような副作用のない式文は**警告**（v1 では許容）。

### 5.9 関数定義 `[ch8]`

```python
def name(p1: T1, p2: T2) -> R:
    body
```

- ネストした関数定義は **v1 未対応**（トップレベルとクラス内メソッドのみ）
- 前方参照可（ファイル後方の関数を呼べる。2 パス方式で実装する）
- クロージャ・第一級関数は v1 未対応

### 5.10 クラス定義 `[ch12]`

```python
class Token:
    kind: int
    text: str

    def init(self, kind: int, text: str) -> None:
        self.kind = kind
        self.text = text

    def is_eof(self) -> bool:
        return self.kind == 0
```

- フィールドはクラス本体の先頭にまとめて宣言する
- **継承なし**（v1）
- インスタンス生成は `Token(0, "")`。`init` メソッドがあれば呼ばれる
- インスタンスは常にヒープに確保され、**参照セマンティクス**（Python と同じ）
- `self` は第 1 引数として明示的に書く（Python と同じ）

**⚠️ Python との差異**：コンストラクタ名は `__init__` ではなく `init`。
ダンダー（`__x__`）記法を導入しないためです。

### 5.11 extern 宣言 `[ch14]`

C の関数を呼ぶための宣言です。

```python
extern def pl_read_file(path: str) -> str
extern def pl_system(cmd: str) -> int
```

- 本体を持たない（`:` もブロックも書かない。改行で終わる）
- リンク時に C 側の実体に解決される
- **名前修飾（マングリング）を行わない**（C 側で名前が決まっているため）
- **`bool` は引数にも戻り値にも使えない**（`i1` と C の `_Bool` の ABI が
  環境依存になるため。`int` で受けて `n == 1` と書く）
- 使える型：`int` / `str` / `list[T]` / クラス / 戻り値の `None`

**★ `extern` は標準ライブラリ（`lib/*.po`）の中に閉じ込めるのが作法です。**
利用者は `io.read_file` を使い、C の関数名を知りません。

### 5.12 import `[ch13]`

```python
import lexer

def main() -> int:
    t: lexer.Token = lexer.make(1, "hi")
    print(lexer.MAX_KIND)
    return 0
```

- **モジュール名 = ファイル名から `.po` を除いたもの**（`import lexer` → `lexer.po`）
- 探索するのは**入口ファイルのあるディレクトリ**だけ（v1）
- `import` は**トップレベルにのみ**書ける（6.3）
- トップレベルの名前は**すべて公開**される（非公開の規約は設けない）
- **他モジュールの名前は必ず修飾して使う**（`lexer.Token`。`Token` とは書けない）
- 型注釈の修飾は **1 段だけ**（`lexer.Token` / `list[lexer.Token]`）
- **モジュール名と同じ名前**の変数・関数・クラスは宣言できない
- **循環 import はエラー**（依存関係は DAG に保つ）

**採用しないもの**：`from X import Y`／`import X as Y`／`from X import *`／
パッケージ（`a.b.c`）。理由は第13章 13.1 節。

## 6. プログラム構造

### 6.1 エントリポイント

```python
def main() -> int:
    return 0
```

- `main` は**引数なし**、戻り型 `int` でなければならない
- 戻り値がプロセスの終了コードになる（下位 8bit のみ OS に伝わることに注意）
- コンパイラは `main` を LLVM の `i32 @main()` にラップする

### 6.2 グローバル変数 `[ch5]`

```python
counter: int = 0
```

- 初期化式は**コンパイル時定数**でなければならない（v1 の制限）
- 関数から自由に読み書きできる（`global` 宣言は不要）

### 6.3 トップレベルに書けるもの

トップレベルに**実行文は書けません**（Python と違う点）。書けるのは：

- グローバル変数宣言
- `def` / `class` / `extern` / `import`
- コメント・空行

**🤔 なぜ？** トップレベルに実行文を許すと「モジュールの初期化順序」という厄介な問題が発生します。
コンパイル言語では `main` を唯一の入口にするのが単純で予測可能です。

---

## 7. 組み込み関数

| 関数 | シグネチャ | 説明 | 章 |
|---|---|---|---|
| `print` | `(int) -> None`<br>`(str) -> None`<br>`(bool) -> None`<br>`(float) -> None` | 標準出力に出力し改行。型ごとにオーバーロード | ch7 |
| `len` | `(str) -> int`<br>`(list[T]) -> int` | 長さ | ch9 |
| `str` | `(int) -> str`<br>`(bool) -> str`<br>`(float) -> str` | 文字列化 | ch9 |
| `int` | `(str) -> int`<br>`(float) -> int` | 整数化（パース失敗は実行時エラー） | ch9 |
| `float` | `(int) -> float` | 浮動小数点化 | ch9 |
| `ord` | `(str) -> int` | 先頭 1 バイトのコード | ch9 |
| `chr` | `(int) -> str` | 1 バイト文字列を作る | ch9 |
| `exit` | `(int) -> None` | プロセス終了 | ch9 |
| `panic` | `(str) -> None` | メッセージを stderr に出して異常終了 | ch9 |

**🤔 なぜ `print` だけオーバーロードを許すのか**
ユーザー定義関数のオーバーロードは実装しません（名前解決が複雑になる）。
しかし `print` を型ごとに `print_int` / `print_str` と書き分けるのは
教材としてストレスが大きすぎるため、**組み込み関数に限り**コンパイラが特別扱いします。

## 8. 実行時エラー

以下は実行時に検出し、stderr にメッセージを出して終了コード 1 で異常終了します。

| 条件 | メッセージ |
|---|---|
| 0 除算 | `runtime error: division by zero` |
| リスト添字範囲外 | `runtime error: index out of range: i (len=n)` |
| `None` のフィールドアクセス | `runtime error: None has no field` |
| メモリ確保失敗 | `runtime error: out of memory` |

例外機構（`try`/`except`）は v1 では**採用しません**。回復不能エラーは即終了です。

## 9. メモリ管理

**v1 では解放しません**（`malloc` するのみ、`free` しない）。

**🤔 なぜ？**
GC も参照カウントも、それ自体が大きなプロジェクトです。
そして本命のターゲットである「コンパイラ」は**短命なプロセス**なので、
プロセス終了で OS がまとめて回収するのに任せて問題ありません。

詳細と将来の選択肢は [../design/memory-model.md](../design/memory-model.md) にまとめます。

## 10. Python との差異まとめ

Polonium を書くときに引っかかりやすい非互換の一覧です。

| # | Python | Polonium | 理由 |
|---|---|---|---|
| 1 | 型注釈は任意 | **必須** | 静的型付けのため |
| 2 | `int / int` → float | **エラー**（`//` を使う） | 暗黙変換なし |
| 3 | `-7 // 2 == -4` | `-7 // 2 == -3` | `sdiv` の意味を採用 |
| 4 | `if xs:` が使える | **`if len(xs) > 0:`** | truthiness なし |
| 5 | `a < b < c` | **エラー** | 比較連鎖なし |
| 6 | `a and b` が値を返す | **`bool` を返す** | 型が一意に決まらない |
| 7 | トップレベルに実行文 | **不可**（`main` が入口） | 初期化順序を持たない |
| 8 | `__init__` | **`init`** | ダンダーを導入しない |
| 9 | 継承・多重継承 | **なし**（v1） | 実装単純化 |
| 10 | 例外 | **なし** | 実装単純化 |
| 11 | 動的属性追加 | **なし** | 静的レイアウト |
| 12 | タブインデント可 | **エラー** | 曖昧さの排除 |
| 13 | 任意精度整数 | **64bit 固定** | マシン値をそのまま使う |
| 14 | クロージャ・lambda | **なし**（v1） | 実装単純化 |
| 15 | シャドーイング可 | **なし**（v1） | 混乱の排除 |

## 11. サンプルプログラム（v1 完成時に動くもの）

```python
# examples/fizzbuzz.po
def fizzbuzz(n: int) -> str:
    if n % 15 == 0:
        return "FizzBuzz"
    elif n % 3 == 0:
        return "Fizz"
    elif n % 5 == 0:
        return "Buzz"
    else:
        return str(n)

def main() -> int:
    for i in range(1, 16):
        print(fizzbuzz(i))
    return 0
```

```python
# examples/token.po
class Token:
    kind: int
    text: str

    def init(self, kind: int, text: str) -> None:
        self.kind = kind
        self.text = text

def main() -> int:
    tokens: list[Token] = []
    tokens.append(Token(1, "hello"))
    tokens.append(Token(2, "world"))
    for t in tokens:
        print(t.text)
    return 0
```
