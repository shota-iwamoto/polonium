# ロードマップ

Polonium が**いまどこまで来ていて、次に何を入れるか**です。

各機能の設計は [design/future-features.md](design/future-features.md) にあります。

---

## 1. 到達点

### 動くもの

| 分類 | 内容 |
|---|---|
| 型 | `int` / `float` / `bool` / `str` / `None` / `list[T]` / `class`（**ジェネリック可**）/ `T \| None` / `rc[T]` / `ptr[T]` / `fn(...) -> T` |
| 式 | 算術・比較・論理（短絡）・ビット演算・添字・**スライス**・フィールド・メソッド・呼び出し・**三項演算子**・**`in` / `not in`**・**f-string** |
| 文 | 宣言・代入・累算代入・`if`/`elif`/`else`・`while`・`for`（`range` / `enumerate`）・`break`/`continue`・`return`・`pass`・**`assert`** |
| 定義 | 関数・クラス（`init` / メソッド / `drop` / **ジェネリック**）・**`interface`**・グローバル変数・`extern`・`import` |
| 安全性 | 所有権（`own`）・借用・可変性（`mut`）・解放（`drop`）・共有（`rc[T]`） |
| エラー処理 | `raises` / `try` / `except` / `raise`（アンワインドなし。戻り値検査） |
| None 安全 | `T \| None` と `is not None` による絞り込み |
| 低レベル | `unsafe:` ブロック・生ポインタ・volatile 読み書き・インライン `asm` |
| 標準ライブラリ | `strings` / `io` / `sys` / `dict`／**数値計算**（`math` / `linalg` / `stats` / `random` / `numeric` / `physics`）。**すべて Polonium で記述** |

### 処理系

| | |
|---|---|
| 実装 | C 版（stage0）約 11,000 行 ＋ Polonium 版（stage1）約 7,500 行 |
| バックエンド | LLVM IR のテキストを出力し、アセンブル・リンクは clang に委譲 |
| セルフホスト | **到達済み** — stage2 と stage3 がバイト単位で一致（不動点） |
| 検証 | テスト 431 件 ＋ 2 実装の出力比較 268 件 ＋ ASan 11 件 |
| 対応環境 | Linux / macOS（Intel・Apple Silicon）/ Windows（MSYS2）/ RISC-V ベアメタル |

### 到達していないところ

**言語として素直に書けない場面が、はっきり 3 つあります。**

1. **クロージャが無い** — 関数型は入りましたが、渡せるのは
   トップレベルの関数だけです。外側の変数を捕まえられません。
2. **タプルが無い** — `for a, b in pairs:` が書けません。
   複数の値を返すこと自体は `Pair[A, B]`（ジェネリクス）で書けます。
3. **内包表記・集合が無い** — `for` と `append` で書きます。

**言語としての大きな穴は埋まりました。** 残りは書きやすさの問題です。

## 2. これから

優先度は **「無いと書けないもの」＞「無いと不便なもの」** の順です。

### 優先度 A — 言語の表現力の穴

| 機能 | なぜ要るか | 規模 |
|---|---|---|
| **タプル・複数戻り値** | 2 つの値を返す。`for a, b in pairs:` もこれ待ち | 中 |
| **クロージャ** | 外側の変数を捕まえる。関数型（`fn`）は 0.3.0 で入った | 中 |

### 優先度 B — 日常的に不便なもの

| 機能 | 内容 |
|---|---|
| **`dict` の `in`** | いまは `d.has(k)`。ジェネリクスと一緒に見直す |
| **文字列の書式指定** | `f"{x:>8}"`（桁揃え）。f-string 自体は 0.3.0 で入った |

### 優先度 C — その先

| 機能 | 内容 |
|---|---|

| 列挙型（`enum`） | いまはグローバル定数で代用している |
| モジュールの名前空間 | `from x import y` / パッケージ |
| 内包表記 | `[f(x) for x in xs]` |
| 演算子オーバーロード | `__add__` 相当 |

### 処理系の宿題

| 項目 | 内容 |
|---|---|
| **セルフホストの機能差** | `--drop` と所有権検査（`ownck`）が C 版にしかない。Polonium 版へ移植する |
| **コンパイラ自身が検査を通らない** | 下記参照。**いちばん大きな宿題** |
| **一時値の解放** | 式の途中で作られた値が解放されない（`make drop-leak` で検出できる） |
| **`float` の往復** | `float → str → float` が元に戻らない（6 桁で丸めている） |
| **エラー処理の網羅性** | `except` が全ての `raises` を捕らえているかの検査 |

### ⚠️ コンパイラ自身が安全性検査を通りません

`selfhost/` を厳密に検査すると **284 件**の指摘が出ます（0.4.0 時点）。

| 種別 | 件数 | 内容 |
|---|---|---|
| `E-MOVE-1` | 151 | 移動済みの値の使用 |
| `E-BORROW-3` | 71 | 借用した値をフィールドに保存 |
| `E-BORROW-4` | 43 | 借用した値を返す |
| その他 | 19 | `E-BORROW-1/5/6` / `E-MUT-1` |

**これは検査の誤検出ではありません。** 実際に確かめました。

```python
def store_and_return(h: mut Holder) -> Node:
    t: Node = Node(7)
    h.n = t
    return t          # ← E-MOVE-1
```

`--drop` を付けてこれを実行すると **null を返して落ちます**
（`h.n = t` でスロットが null 化されるため。決定 D17）。指摘は正しいのです。

**そして、書き直しでは直りません。** フィールドから読み直す形にしても、
今度は「借用した値を返している」（`E-BORROW-4`）になり、実行すると
二重解放で落ちます。**このパターンは所有権だけでは表現できません。**

#### 答えは `rc[T]` です

```python
class Holder:
    n: rc[Node] | None

def store_and_return(h: mut Holder) -> rc[Node]:
    t: rc[Node] = rc(Node(7))
    h.n = t
    return t          # ★ 警告なし。最後の 1 つが手放したときに解放される
```

確認しました：**警告 0 件、正しく共有され、解放は 1 回だけ**です。
この 3 つの結論は `tests/cases/own_share_needs_rc.po` と
`tests/cases/warn_share_without_rc.po` に固定してあります
（結論が変わったら気づけるように）。

つまり **所有権モデル自体は完結しています。** 足りないのは
「コンパイラのソースを `rc[T]` へ移行する作業」です。

⚠️ 一度試して**取り下げました**（決定 D20：一括で `own` を付けたら
違反が 229 → 494 に増えた）。引数を `own` にすると、今度は呼び出し側で
移動が起きて連鎖するためです。**`rc[T]` が要る場所を 1 つずつ見極める**
必要があり、機械的な置換では済みません。

## 3. 設計上ぶれさせないこと

新しい機能を足すときも、この 5 つは変えません。

1. **暗黙の型変換をしない。** `int` と `float` すら混ざりません。
2. **GC を入れない。** 所有権と `rc[T]` で足りるようにします。
3. **例外でスタックを巻き戻さない。** `raises` は戻り値の検査です。
4. **呼び出し側に印を書かせない。** `&x` も `x.clone()` も不要にします。
5. **2 つの実装を一致させ続ける。** C 版と Polonium 版が同じ IR を出すこと（`make test`）、
   そして stage2 == stage3（`make bootstrap`）を壊さないこと。
