# 第28章 `rc[T]` — 共有所有

> **この章のゴール**
> 「所有者を 1 つに決められない」データを扱えるようにする。
> **第26章で行き止まりになった 228 件は、これを待っていました。**
>
> ```bash
> $ cat t.po
> class Node:
>     name: str
>     child: rc[Node] | None
>     def init(self, name: own str) -> None:
>         self.name = name
>         self.child = None
>     def attach(mut self, c: rc[Node]) -> None:
>         self.child = c          # ★ 借りた rc をフィールドに保存できる
>
> def main() -> int:
>     root: rc[Node] = rc(Node("root"))
>     kid: rc[Node] = rc(Node("child"))
>     root.attach(kid)
>     return 0
> ```

第22〜25章で作った所有権は「所有者はいつも 1 人」という前提でした。
木・グラフ・シンボル表のように、**同じものを何か所からも指したい**構造では
その前提が成り立ちません。第26章で、`own` を機械的に足していったら
違反が 229 件 → 494 件に**増えた**のがその証拠です。

**★ `rc[T]` は「最後の手段」です**（仕様 §7.3）。まず借用で足りないか、
添字で表せないかを考えてから使います。

## 28.2 表現：中身を埋め込まず、ポインタを 1 本持つ

設計（[ownership.md §7](../design/ownership.md)）は「中身を埋め込む」形でした。

```
  ┌──────────┬──────────┬─────────────┐
  │ strong   │ borrow   │ T の中身 …   │   ← 設計の当初案
  └──────────┴──────────┴─────────────┘
```

実装では**ポインタを 1 本持つ**形にしました。

```c
typedef struct {
    long long strong;
    long long borrow;
    void *value;      // ★ 中身へのポインタ
} PlRc;
```

**🤔 なぜ変えたのか**：Polonium の所有型（`str` / `list` / class）は**すべてポインタ**です。
埋め込む形にすると型ごとにレイアウト計算が要りますが、ポインタを持つなら
**どの型でも同じ形**になります。`rc(Node("a"))` は「既にあるオブジェクトに
数え札を付ける」だけの操作になり、生成も 1 命令で済みます。

```llvm
  %t.1 = call ptr @rc.Node.init(...)      ; ふつうにインスタンスを作って
  %t.2 = call ptr @pl_rc_new(ptr %t.1)    ; 数え札を付ける
```

## 28.3 共有型は「移動しない」

仕様 §2 は型を 3 つに分けていました。**`rc[T]` は 3 つ目の「共有型」です。**

```python
node: rc[Node] = rc(Node("a"))
other: rc[Node] = node          # ✅ 移動ではなく共有（カウント 2）
print(node.name)                # ✅ node はまだ使える
```

所有権検査（ownck）に 1 か所足すだけです。

```c
    // ★ 「所有者を 1 つに決められない」ためにある型なので、移動として扱いません。
    //   束縛した側は**新しい参照**を持ちます（カウント +1）。
    if (n->type && n->type->kind == TY_RC) {
        use_expr(o, f, n);
        return true;      // ← 「この値を所有した」（＝ 解放の対象になる）
    }
```

**★ `true` を返すのが要点です。** 移動はしないが、**後始末（カウントを減らす）は要る**。
第25章で `move_expr` の戻り値を「実際に移動したか」ではなく
「**束縛した側が所有するか**」という意味にしておいたので、ここに素直に乗りました。

## 28.4 いつ増やして、いつ減らすか

| 操作 | すること |
|---|---|
| `rc(x)` | 新しい数え札（`strong = 1`） |
| **場所から読んで別の場所に置く**（代入・フィールド・`append`・`return`） | `pl_rc_retain`（+1） |
| スコープの終端 | `pl_rc_release`（−1。0 なら中身を解放） |
| 借用として渡す（ふつうの引数） | **何もしない**（呼び出しの間は呼び出し側の参照が生きている） |

```c
static char *maybe_retain(Emitter *e, Node *rhs, char *val) {
    if (!e->drop || !rhs || rhs->type->kind != TY_RC) return val;
    if (rhs->kind != ND_VAR && rhs->kind != ND_FIELD && rhs->kind != ND_INDEX)
        return val;                    // ★ rc(...) や戻り値は「新しい参照」
    ...  call @pl_rc_retain ...
}
```

**⚠️ `retain` と `release` は対です。** 解放を挿さない（`--drop` 無し）ときは
**どちらも出しません**。数が合わないくらいなら、何もしないほうが安全です。

**★ 「場所から読んだときだけ増やす」で足ります。** `rc(...)` の結果と関数の戻り値は
**新しい参照**なので、そのまま置けます。逆に、ふつうの引数（借用）で渡すときは
増やしません——呼び出しの間、呼び出し側の参照が生きているからです（仕様 §4.4）。

## 28.5 自動デリファレンス（`with` を書かせない）

仕様 §7.2 は、中身を使うときに `with node.borrow() as n:` と書く形でした。
実装では**そのまま `node.name` と書けるように**しました（Rust の `Deref` と同じ）。

```c
// rc[T] は「中身のように」使える（第28章）。
static Type *auto_deref(Type *t) {
    return t && t->kind == TY_RC ? t->elem : t;
}
```

**🤔 なぜ書かせないことにしたのか**

`with` を毎回書かせると、木やグラフを扱うコードが読めなくなります。
それは **`rc[T]` を用意した目的（所有権で書けない構造を書けるようにする）を裏切ります。**
決定 D3（「借用も `clone()` も書かせない」）と同じ理由です。

**⚠️ 代わりに失うもの**：`borrow()` / `borrow_mut()` の**実行時検査**（同時可変の禁止）。
Polonium は単一スレッドで、添字は実行時に範囲検査するので、
**メモリ安全（二重解放・解放後の使用が無い）は保てます**。
失うのは「反復中に書き換える」ような論理的な間違いの検出です。
ランタイムには数え札（`pl_rc_borrow` / `pl_rc_borrow_mut`）を用意してあるので、
`with` を入れるときはそこに繋ぎます（第29章以降の宿題）。

## 28.6 第26章の行き止まりが解ける

第26章で `own` を足していって行き止まりになったのは、この形でした。

```python
    def init(self, name: str) -> None:
        self.name = name        # ❌ E-BORROW-3：借用をフィールドに保存できない
```

`rc[T]` なら**保存できます**。保存＝共有だからです。

```python
    def attach(mut self, c: rc[Node]) -> None:
        self.child = c          # ✅ カウントが 1 増えるだけ
```

```bash
$ ./build/poloniumc --drop --deny-move --deny-borrow --deny-mut t.po -o t
（違反なし）
```

**★ これが第29章（セルフホスト v2）の下ごしらえです。**
`selfhost/` に残る 228 件のうち、共有が原因のものは
「その型を `rc[T]` にする」ことで解けます。

## 28.9 まとめと次章の予告

この章でやったこと：

- `rc[T]` を**共有型**として実装した（代入は移動ではなく共有）
- 表現を「中身の埋め込み」から**ポインタ 1 本**に変え、型ごとの場合分けを消した
- 増やすのは「場所から読んで別の場所に置くとき」だけ、という規則にした
- **自動デリファレンス**にして、`with` を書かせないことを選んだ（D3 と同じ判断）
- 第26章の行き止まり（借用をフィールドに保存できない）が解けることを確かめた

次章（第29章）は **セルフホスト v2**——この本の山場です。

- Polonium 版コンパイラ（`selfhost/`）に **v2 の構文**（`raises` / `try` / `except` / `rc[T]`）を教える
- 所有権検査と解放の挿入を **Polonium で書き直す**
- `selfhost/` 自身を v2 の規則に移行し、**不動点を取り戻す**

**★ 「自分自身を、自分の新しい規則でコンパイルできる」ところまで来れば、v2 は完成です。**
