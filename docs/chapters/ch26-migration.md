# 第26章 既存コードの v2 移行（と、仕様が壊れた話）

> **この章のゴール**
> `lib/` と `selfhost/` を v2 の規則で書き直す。

[design/ownership.md §8](../design/ownership.md) はこう書いていました。

> **★ 方針：`rc[T]` を使わずに書ききれることを目標にします。**
> 書ききれなければ、それは仕様が厳しすぎるという証拠なので、仕様側を見直します
> （**コンパイラ自身が言語仕様のテストケース**）。

**この章は、その方針が実際に働いた記録です。** 結果を先に書きます。

## 26.1 まず測る

移行は「直せそうなところから直す」のではなく、**全体を数えてから**始めます。

```bash
# 上限を外したコンパイラを 1 つ作って、全部出させる
$ clang ... -DOWNCK_MAX_REPORT=100000 src/*.c -o /tmp/plc-all
$ /tmp/plc-all selfhost/main.po -o /tmp/s1 2>&1 | grep -oE "warning\[E-[A-Z]+-[0-9]\]" | sort | uniq -c
  76 warning[E-BORROW-3]      借用の保存
  33 warning[E-BORROW-4]      借用の返却
 116 warning[E-MOVE-1]        移動済みの値の使用
  75 warning[E-MOVE-2]        フィールドからの取り出し
 154 warning[E-MUT-1]         読み取り専用への書き換え
```

**★ 数える前に直し始めないこと。** どの検査が何件で、どういう形が多いのかが分かって
初めて「機械的に直せるもの」と「設計を変えないと直らないもの」を分けられます。

## 26.2 仕様が壊れた ①：フィールドを読めない

`E-MOVE-2`（第25章で入れた「フィールドからの取り出しの禁止」）の中身を見て、手が止まりました。

```python
   7 n.name = name_tok.text          # 別のオブジェクトへ写す
   4 n.ir_name = v.ir_name
   2 nx: ast.Node | None = cur.next  # ★ 連結リストをたどる
   2 d: ast.Node | None = root.body  # ★ 木をたどる
```

**⚠️ `nx = cur.next` が書けないということは、連結リストをたどれないということです。**
コンパイラは AST（木）とシンボル表（リスト）でできています。**この規則では、
この言語で自分自身を書けません。**

第25章で「フィールドごとの drop フラグを持ちたくない」という**実装の都合**から
決めた規則（D15）でした。**実装の都合が、言語を使えなくしていた**わけです。

---

## 26.3 仕様を直す：読み出しは借用、寿命はスコープ

**★ 決定 D18：フィールド・要素の読み出しは「移動」ではなく「借用」。**（D15 を撤回）

```python
    nx: ast.Node | None = cur.next    # ✅ nx は cur.next を借りているだけ
```

借用なら、解放の問題も起きません。**借りものは解放しない**からです（第25章 §25.5）。
第22章から「添字の読み出し（`t = xs[i]`）は借用」と決めていたので、
**フィールドも同じ扱いにそろえた**だけ、とも言えます。

ただし、これだけでは穴が開きます。

```python
def f() -> int:
    s: str = "x"
    if cond:
        b: Box = Box("y")
        s = b.label        # ← b は if を抜けると消える。s は宙に浮く
    return len(s)          # ❌ 解放済みのメモリを読む
```

**★ 決定 D19：借りものは、貸し手より長生きできない（`E-BORROW-6`）。**

```
warning[E-BORROW-6]: 借りたもの（'b' の一部）は、'b' より長く持てません
```

実装は**スコープの深さを数えるだけ**です。ownck が `ND_BLOCK` に入るたびに
深さを 1 増やし、借用の根が宣言された深さと、代入先の変数が宣言された深さを比べます。

```c
    if (tgt && !proto.is_param && tgt->depth < proto.depth) { ... E-BORROW-6 ... }
```

**★ 借用の寿命を「呼び出しの間」に固定した仕様 §4.4 の考えを、
ローカル変数どうしにも当てはめただけです。** 新しい理屈は要りませんでした。

この 2 つの変更で、`selfhost/` の違反は **454 件 → 379 件**になりました。
`E-MOVE-2` の 75 件が消え、代わりに**本物のダングリング参照 4 件**（`E-BORROW-6`）が
見つかっています。

## 26.4 `mut` の移行（154 件）— 機械的に片付く

`E-MUT-1` は「`mut self` / `mut` を足す」だけで直ります。**診断が直し方を持っている**ので、
出力を読んで自動で当てられます。

```
note: 'self' は読み取り専用で借りています
   --> selfhost/parser.po:37:14
    = ヒント: メソッドの宣言を 'def advance(mut self, ...)' にしてください
```

診断の `note:` は**直す場所そのもの**（引数の宣言）を指しています。
そこで、次の手順を収束するまで繰り返すスクリプトを書きました。

```
① コンパイルして E-MUT-1 の note 位置を全部集める
② その位置に "mut " を挿入する
③ ①へ戻る（新しく見つかる分がある：mut のメソッドを呼ぶ側も mut になる）
```

```
round 0: E-MUT-1 = 154   → 71 件に mut を付けた
round 1: E-MUT-1 = 150   → 54 件
round 2: E-MUT-1 =  60   → 30 件
round 3: E-MUT-1 =   3   →  3 件
round 4: E-MUT-1 =   0   ✅
```

**🤔 なぜ 1 回で終わらないのか**：`mut self` を付けたメソッドを呼ぶ側は、
そのオブジェクトを**可変で借りる**ことになります。すると呼び出し側の引数にも
`mut` が要る——という連鎖が起きます。**可変性は呼び出しの木を上に伝わります。**

結果は 136 行の変更（`mut self` が大半）。**IR は変わりません**（`mut` は検査だけの注釈）。

**★ そして、ここで初めて `E-BORROW-5`（借用の衝突）が 4 件見つかりました。**
第24章で「0 件なのは `mut` が 1 つも無いからだ」と書いたとおりです。
**検査は、書かれていないものは見つけられません。**

## 26.5 `own` の移行を試して、やめた（229 → 494）

次は `E-BORROW-3`（借用の保存）です。診断の言うとおり `own` を足してみました。

```python
    def init(self, name: str) -> None:      →   def init(self, name: own str) -> None:
        self.name = name
```

同じ要領で 93 か所に `own` を足した結果——

```
移行前： 229 件
移行後： 494 件   ← 増えた
  E-BORROW-1  261 件（借用した値を own 引数へ渡せない）
  E-MOVE-1    195 件（own に渡した後で使っている）
```

**⚠️ 所有権は、呼び出し側へ伝播します。**
`init` が所有権を要求すると、`Token(...)` を作る側が所有権を持っていなければならず、
その値は**さらに上流**から所有権ごと渡ってこなければなりません。
`selfhost/` のように「1 つのトークンを、字句解析器・構文解析器・診断が同時に指す」
構造では、**この伝播はどこにも着地しません**。

**★ これは「仕様が厳しすぎる」のではなく、「この構造には共有が要る」という結論です。**
設計 §7 が最初から用意していた逃げ道——`rc[T]`——の出番です。

そこで `own` の移行は**まるごと戻し**、`mut` の移行だけを残しました。

```bash
$ git checkout selfhost/        # own の 93 か所を捨てる
$ python3 fix_mut.py            # mut だけをやり直す
```

**⚠️ 「せっかく直したのだから残したい」は禁物です。**
中途半端に `own` が入った状態は、後で `rc[T]` に置き換えるときに邪魔になります。

## 26.6 `lib/` を 0 件にする — `copy(x)` が必要になった

`lib/` は 5 件だけなので、**移行の型（かた）を作る**ために手で直しました。

| 場所 | 違反 | 直し方 |
|---|---|---|
| `dict.set` | `E-MUT-1` ×3 | `def set(mut self, ...)` |
| `dict.set` | `E-BORROW-3` | `k: own str`（辞書は鍵を所有する） |
| `strings.replace` | `E-BORROW-4` | `s: own str` |

`dict.set` が鍵の所有権を要求するようになったので、今度は**呼ぶ側**が動きます。

```python
    for word in strings.split(line, " "):    # word はリストの要素＝借りもの
        counts.set(word, ...)                 # ❌ E-BORROW-1
```

借りたものを保存したいときの逃げ道が、決定 D8 で決めてあった `copy(x)` です。
**移行の途中で必要性が確定したので、ここで実装しました。**

```c
// runtime.c
char *pl_str_copy(const char *s) {
    long long n = pl_str_len(s);
    char *p = pl_str_alloc(n);      // ★ ヒープに作るので「静的」の印は付かない
    memcpy(p, s, (size_t)n + 1);
    return p;
}
```

```python
    counts.set(copy(word), counts.get_or(word, 0) + 1)   # ✅
```

**⚠️ いまは `str` の複製だけです。** `list[T]` や class の複製は「要素まで複製するのか」
という設計が要るので、`rc[T]`（第28章）と一緒に決めます。

これで **`lib/` と `examples/` は 0 件**になりました。

## 26.7 標準ライブラリが解放付きで動く

移行できたということは、**解放を有効にして動かせる**ということです。

```bash
$ ./build/poloniumc --drop --keep-ll examples/wordcount.po -o wcd
$ clang -fsanitize=address wcd.*.ll runtime/runtime.c -o wcd.asan
$ ./wcd.asan examples/sample.txt
the: 3
quick: 1
...
（AddressSanitizer の報告なし）
```

**★ 5 つのモジュール（`io` / `strings` / `dict` / `sys` / 本体）が、
自動的な解放付きで、二重解放も解放後の使用もなく動きました。**
第22章から積み上げてきたものが、初めて「実際に動くプログラム」として形になった瞬間です。

テストにも固定しました（`drop_lib_dict.po`）。`make drop-asan` が毎回確かめます。

## 26.8 残った 228 件が示していること

| 検査 | 件数 | 何を言っているか |
|---|---|---|
| `E-MOVE-1` | 108 | 「同じ値を 2 か所で持っている」 |
| `E-BORROW-3` | 78 | 「借りたものをフィールドに保存している」 |
| `E-BORROW-4` | 34 | 「表から引いた値を返している」 |
| `E-BORROW-5` | 4 | 「同じものを可変と共有で同時に渡している」 |
| `E-BORROW-6` | 4 | 「内側で作ったものを外側に持ち出している」 |

**★ 228 件すべてが、同じ 1 つのことを言っています：
「このデータは、所有者を 1 つに決められない」。**

```python
    # トークンは、字句解析器のリストにも、AST のノードにも、診断にも現れる
    n.tok = t
    # シンボル表の要素は、表にも、それを引いた側にも現れる
    return f
```

`E-BORROW-5` の 4 件と `E-BORROW-6` の 4 件は**本物の危険**（同時可変・寿命超過）なので、
第29章で個別に直します。残りは共有の問題なので、**`rc[T]` を入れてから**手を付けます。

**⚠️ だから、この章では既定の切り替え（`--deny-*` と `--drop` を on にする）は行いません。**
`selfhost/` が通らないうちに既定にすると、コンパイラ自身がビルドできなくなります。
切り替えは**第29章**（セルフホスト v2）で行います。

## 26.10 まとめと次章の予告

この章でやったこと：

- 移行の前に**全体を数えた**（454 件、検査ごとの内訳と典型パターン）
- **仕様を 2 つ直した**：フィールドの読み出しは借用（D18）、借用はスコープを超えない（D19）
- `mut` を機械的に移行した（154 件 → 0。診断が直し方を持っていたので自動化できた）
- `own` の移行を試し、**229 → 494 に増えたので撤回した**（所有権は上流へ伝播する）
- `lib/` を 0 件にし、その過程で `copy(x)` を実装した
- **標準ライブラリを使う実プログラムが、解放付きで ASan を通った**

次章（第27章）は **`raises` / `try` / `except`** です。
エラー処理は所有権とは独立に進められるので、`rc[T]`（第28章）の前に片付けます。
アンワインドしない設計（戻り値検査への脱糖）なので、**カーネルでも使えます**
（[design/error-handling.md](../design/error-handling.md)）。

そして**第28章で `rc[T]`**、**第29章でセルフホスト v2**——
この章で残した 228 件は、そこで片付きます。
