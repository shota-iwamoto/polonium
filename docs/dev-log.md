### 判断したこと（と理由）

| # | 判断 | 理由 |
|---|---|---|
| 1 | **LLVM IR テキストを出力する**（C API を使わない） | C 側のコードが `sb_printf` だけになり読みやすい。生成物を目で読んで学べる。**決定的な理由：セルフホスト時に Polonium 側に必要なのが「文字列を組み立てて出力する」機能だけになる。** C API 方式だと FFI 機構が言語に必要になり難易度が跳ね上がる |
| 2 | **全変数を `alloca` に置き、`phi` を生成しない** | SSA 構築（支配辺境の計算）はコンパイラ理論の難所。LLVM の `mem2reg` が最適な形に直してくれるので、素朴に書いて任せる。実測で確認済み（下記） |
| 3 | **型注釈を必須にし、型推論を入れない** | 型検査器が「調べるだけ」になり「推論する」必要がなくなる。実装が劇的に単純になる |
| 4 | **`str` は NUL 終端バイト列**（`{ptr,len}` ではない） | C 関数にそのまま渡せる。ランタイムが極小で済む。代償は `len()` が O(n) と、文字列中に NUL を置けないこと。コンパイラ用途では問題にならない。第9章で再検討する |
| 5 | **`free()` を呼ばない** | コンパイラは短命プロセス。解放タイミングは実質「プロセス終了時」しかない。`free` を書くと二重解放バグの余地が生まれ、得るものがない |
| 6 | **`int / int` をエラーにする**（`//` を使わせる） | 暗黙の型変換を入れないため。型昇格ルールは型検査器を複雑にする |
| 7 | **`//` は `sdiv`（切り捨て）で Python の floor 除算と非互換にする** | `sdiv` 1 命令で済む。`-7 // 2` が Python では `-4`、Polonium では `-3` になる。既知の非互換として仕様書に明記 |
| 8 | **truthiness を採用しない**（`if xs:` を禁止） | `bool` 以外を条件式に許すと型検査が緩む。`if len(xs) > 0:` を書かせる |
| 9 | **タブインデントを字句エラーにする** | タブ幅の解釈で意味が変わるコードは言語の欠陥。実装も単純になる |
| 10 | **トークンを配列で持つ**（リンクリストではない） | 任意の先読みが O(1)（第5章で `x : int` の判別に 2 トークン必要）。Polonium 移植時に `list[Token]` として自然 |
| 11 | **AST は「全部入り」の 1 構造体** | C で共用体を安全に扱うと冗長。chibicc/tcc など実績ある方式。1 ノード 150 バイト程度なので無駄も許容範囲 |
| 12 | **`main` はラッパ方式**（`@pl_main` + `@main`） | `main` だけ特別扱いする分岐をコード生成器に入れたくない。`-O2` でインライン展開され消えるのでコストゼロ（実測で確認） |
| 13 | **`--dump-tokens` / `--dump-ast` を第1章で作る** | 開発速度を決める中核ツール。さらに**第16/17章でセルフホスト版の検証に使う「正解出力」になる** |
| 14 | **エラーは最初の 1 件で `exit(1)`** | エラー回復（複数報告）は独立した難問。v1 のスコープ外 |
| 15 | **CMake を使わず Makefile 1 枚** | 依存が増え、生成物が読めなくなる。10 ファイル程度に CMake は過剰 |
| 16 | **設計ドキュメントを実装より先に全部書く** | 「何を作るか」が曖昧なまま実装すると、後で全部書き直しになる |

### つまずいたこと

**① `clang -print-target-triple` を使うと警告が消えない** ⚠️

IR に `target triple` を書かないと clang が警告を出すので、
ビルド時に triple を取得しようとした。直感的に `-print-target-triple` を使ったが、**警告が消えなかった**。

```bash
$ clang -print-target-triple
x86_64-apple-darwin25.5.0          # ← これを .ll に書くと…

$ clang t.ll -o t
warning: overriding the module target triple with x86_64-apple-macosx26.0.0
```

macOS の clang は `-print-target-triple`（`darwin<カーネル版>`）と
IR に書く triple（`macosx<OS版>`）で**表記が違う**。

**解決**：clang 自身に空の C ファイルの IR を吐かせて抜き出す。

```makefile
HOST_TRIPLE := $(shell $(CC) -S -emit-llvm -x c /dev/null -o - 2>/dev/null \
                 | sed -n 's/^target triple = "\(.*\)"$$/\1/p')
```

Linux でも同じ方法が使える。

**② `mem2reg` は定数畳み込みをしない**

ドキュメントに「`mem2reg` を掛けると `ret i32 22` になる」と書いていたが、実測すると違った。

```llvm
; opt -passes=mem2reg の実際の出力
define i32 @main() {
entry:
  %t1 = add i64 20, 2      ; ← 定数計算は残る
  %t3 = trunc i64 %t1 to i32
  ret i32 %t3
}
```

`mem2reg` は「メモリ経由をレジスタ経由に変える」だけ。
定数畳み込みは別のパスの仕事なので、`-O2` が必要だった。

**正しい理解**：`mem2reg` が土台を作り、その上で他のパスが働く分業。
`docs/reference/llvm-ir-primer.md` を実測結果に合わせて修正した。

**③ 配列長リテラルのエラーメッセージが直感と逆**

```llvm
@.str.0 = private unnamed_addr constant [14 x i8] c"hello, polonium\0A\00"
```

```
error: constant expression type mismatch: got type '[15 x i8]' but expected '[14 x i8]'
```

`got` が**正しい長さ**（15）、`expected` が**自分が書いた値**（14）。
「got = 自分が書いたもの」と読むと混乱する。
→ `got` の数字をそのまま書き写せば直る、と用語集ドキュメントに注記した。

**④ `-Wall -Wextra` で未使用関数の警告が出た**

第5章で使う予定の `peek_at()` を先に書いたら
`warning: unused function 'peek_at'` が出た。

**判断**：警告 0 件の状態を保つことを優先し、コメントアウトして
「第5章で追加する」と注記した。
**理由**：警告を放置する習慣がつくと、本物のバグを見逃す。

### つまずいたこと

**① `**` の検査を `unary()` の入口に置いてしまった** ⚠️

テスト `err_pow_unsupported.po` が落ちて発覚。
`2 ** 10` が「式の後に余分なトークンがあります」になった。

原因：**`unary()` は「オペランドの先頭」でしか呼ばれない。**
`**` は基数を読み終えた**後**に現れる後置的な演算子なので、
`unary()` の入口では絶対に出会えない。

修正：文法どおり `power ::= primary [ "**" unary ]` の位置に `power()` 関数を作り、
`primary()` を読んだ後に判定するようにした。

**学び**：
- 前置演算子（`-x` `~x` `not x`）→ オペランドの**前**で判定
- 後置演算子（`**` `f(x)` `a[i]` `a.b`）→ オペランドを**読んだ後**で判定
- 第10章（`a[i]`）と第12章（`a.b`）の `postfix` で同じ区別が効く
- 「まだ実装しないから関数を作らなくていい」という判断が誤りだった。
  `grammar.md` には最初から `power` があった。**文法定義に従って関数を配置すべき**

**② `expect()` が未使用になり警告が出た**

`primary()` が `TK_INT` を直接扱うようにしたため、第1章の `expect()`（種別指定版）が
未使用になった。記号版 `expect_punct()` が新たに必要だったので置き換え、
種別版は「第4章で NEWLINE/INDENT に必要になる」とコメントで残した。

第1章の `peek_at()` と同じパターン。**警告 0 件を保つ方針は維持。**

### つまずいたこと

**① 「この入力は起きない」判断が、自分の別の変更で無効になった** ⚠️ 今回の最大の学び

`diag.c` を書いたとき、UTF-8 の表示幅計算は不要と判断してコメントに理由を書いた：

> 識別子もリテラルも ASCII のみ。日本語が書けるのはコメントの中だけで、
> **コメントは行末まで続くのでその後ろにコードは来ない**。
> よって「キャレットより前に日本語がある」状況は起きない。

論理は正しかった。しかし**同じ章で行った EOF 位置の修正**（3.6 節）により、
EOF が「直前の行の末尾」を指すようになり、**EOF がコメント行の末尾を指せるようになった**。

```
error: 空のプログラムです…
  --> err_empty.po:1:37
   |
 1 | # ERROR: 空のプログラムです
   |                                     ^     ← 9 桁ずれた
```

36 バイト / 18 文字 / 表示幅 27 の行で、バイト数ぶん空白を送っていた。

**学び**：
- 「起きない」判断は、他の変更で前提が崩れることがある
- **判断の理由をコメントに書いておいたおかげで**、症状を見た瞬間に
  「あの前提が崩れた」と分かった。理由を残す価値はここにある
- 同じコミット内の 2 つの変更が干渉することもある

**② `while read` + パイプのサブシェル問題を避けた**

テストランナーで `# ERROR:` の複数行を検証するとき、
`echo "$want" | while read` と書くとサブシェルになり、
ループ内で設定した `missing` 変数が外に伝わらない。
ヒアドキュメント（`<<EOF_WANT`）を使って回避した。

**そして「わざと落ちるケース」で検証ロジックが機能することを確認した。**
これをやらないと「常に成功する（何も検証していない）テスト」を抱えたまま進む。

**③ 長さ 0 のトークンで下線が消える**

EOF トークンは `len == 0` なので、素朴に `for (i < tok->len)` と書くと下線が 0 本になる。
`if (under < 1) under = 1;` の保険を入れた。
第4章の `INDENT` / `DEDENT` も長さ 0 なので、この保険が効く。

**④ `utf8_char()` は必ず前進させる**

不正な UTF-8 バイト列でも `*bytes >= 1` を保証しないと無限ループする。
**エラー表示中にコンパイラが固まるのは最悪の体験**なので、
不正バイトは「1 バイト進めて半角扱い」に統一した。

6.8 節に「オペランドの型を間違えると LLVM が

```bash

$ lli bad.ll; echo $?
0                                   # 正しくは 1（4 < 10）
```

**★ この章の本体は「実装」ではなく「移行」だった。**


**予想を書き残しておくと、外れたときに何が想定外だったかが分かる。**

**`str` を回せることに後から気づいた。**
`for c in "abc":` を試したら**何もせずに動いた**。
`len()` と `[]` が `str` にも使えるから（第9・10章）、
脱糖がそのまま通用する。**既にある機能の上に乗せると、章の作業が減る。**

**★ 内部の接頭辞を、言語名から切り離した（`MYTHON_` → `PLC_`、`my_` → `pl_`）。**
言語名は将来また変わるかもしれません。名前を接頭辞に使っていると、改名のたびに
環境変数名・ランタイム ABI・テストスクリプトまで波及します。
`PLC_`（Programming Language Compiler）と `pl_` に固定すれば、**改名しても ABI は動きません**。

**★ 安全性は所有権＋借用を採り、GC も参照カウント既定も採らない。**
最終目標が OS 開発だからです。ランタイムに GC を置くと、そのランタイムが動く前提を
カーネルで用意しなければならなくなります。

**★ ライフタイム注釈を導入しない代わりに、「借用は呼び出しより長生きしない」と決めた。**
Rust の難しさの多くは、安全性そのものではなく**安全性を人間に宣言させる記法**にあります。
借用の寿命を式の内側に固定すれば、リージョン推論も注釈も要らなくなり、
借用検査は「1 つの呼び出しの実引数どうしが衝突しないか」という**局所的な検査**に縮みます。
代償は「借用を返せない・保存できない」ことで、そこは `own` と `rc[T]` で受けます。

**★ 例外はアンワインドしない。`try`/`except` の見た目のまま、戻り値検査に落とす。**
アンワインドは libc と DWARF に強く依存し、ベアメタルでは自前実装が必要になります。
「Python の見た目」と「OS で動く」を両立させるには、構文糖にするのが唯一の道でした。

**★ OS 向け機能は仕様だけ先に固め、実装は ch30 以降にした。**
今の設計判断（ランタイムの分割方針・panic の集約・target triple の外出し）が
後で効いてくるので、**要件は先に書き、実装順序は安全機能を優先**します。

### つまずいたこと

**⚠️ 一括置換で `\b`（単語境界）を使うと、`-DMYTHON_LIB_DIR` や `gen_mython_main` が残る。**
`-D` の `D` と `M` はどちらも単語構成文字なので、境界が成立しません。
2 周目は境界なしで、長い名前から順に置換して解決しました。

**⚠️ 置換はテストデータの中身まで書き換える。**
`tests/cases/str_len.po` の `len("Mython")` が `len("Polonium")` になり、期待値 `6` が合わなくなりました
（`str_index.po` も同様）。**テストが即座に検出**したので、期待値を 8 と `P` / `i` に直しました。
機械的な一括置換ほど、緑のテストの価値が高いという例です。

## 2026-08-26 — 第21章 v2 の土台（`own` / `mut` の構文）

### やったこと

v2 の最初の一歩として、**構文だけ**を通した。意味づけは何もしていない。

- キーワードを 5 語予約：`own` / `mut` / `raises` / `unsafe` / `pragma`
- `ParamMode`（`PM_BORROW` / `PM_MUT` / `PM_OWN`）を `ND_PARAM` に持たせた
- `x: own T` / `x: mut T` / `mut self` を解析（C 版・Polonium 版の両方）
- `--dump-ast` に `(param own xs` の形で出す
- テストを 8 本追加（通るもの 4 / 落ちるもの 4）

### 判断したこと（と理由）

**★ 検査を入れる前に、構文だけを入れて緑にした。**
所有権の検査は構文・AST・セルフホストの 3 か所すべてに変更が要る。
同時にやると、落ちたときに「解析が悪いのか、構文の読み方が悪いのか」が切り分けられない。
構文を先に通しておけば、第22章からは**解析だけを疑える**。

**★ 受け取り方は `Type` ではなく `Node`（引数）に持たせた。**
`Type` はシングルトン共有なので、そこに所有情報を足すと `int` 型が場所ごとに別物になり、
「型の同一性はポインタ比較」という既存の前提が壊れる。
受け取り方は型の性質ではなく**その引数の性質**なので、引数のノードが正しい置き場所。

**★ `own` / `mut` は「型の前」に置く（`xs: mut list[int]`）。**
Python の引数は「名前: 型」という並びで、名前の前に修飾を置くとその並びに割り込む。
型の前なら「`xs` は**可変で借りた `list[int]`**」と型注釈の中で読み切れる。
例外は `self` だけ（型注釈が無いので `mut self`）。**例外が 1 つで済む**ことを確認して決めた。

**★ `PM_BORROW` を列挙の 0 番にした。**
`new_node` は `calloc` でゼロ埋めするので、既定値の初期化コードを 1 行も書かずに済む。

**★ `own self` は禁止した。** self の所有権を奪うと呼び出し元のオブジェクトが消える。
`mut self` を案内するヒントを付けた。

### つまずいたこと

**⚠️ `mut xs: list[int]`（名前の前）を黙って読み飛ばしそうになった。**
`mut` を先読みして覚える実装にすると、self でない場合に `lead` が余る。
**余ったら必ずエラーにする**（「型の前に書きます」と直し方を出す）。
「読めてしまうが意味が無い書き方」を通すのは、後で必ず事故になる。

**⚠️ `--dump-ast` の既定出力を変えなかったのは意図的。**
`(param xs` を `(param borrow xs` にすると、第17章から積み上げた AST 比較
（`make selfhost-test` の 328 件）が全件落ち、本当の差分が埋もれる。
**既定は無出力**にして、`own` / `mut` のときだけ接頭辞を出す。

**⚠️ 第1章の「使わない語も予約する」判断がここで効いた。**
`del` / `try` / `except` / `with` は v1 で予約済みだったので、今回の追加は 5 語で済んだ。
予約していなければ、既存コードが第27章で壊れていた。

## 2026-08-26 — 第22章 ムーブ検査（use-after-move）

### やったこと

- 4 本目のパス `src/ownck.c` / `src/ownck.h` を新設（sema の後、codegen の前）

**★ Q1 を決めた：複製は組み込み関数 `copy(x)` にする（`x.copy()` にはしない）。**
理由は 3 つ。① 仕様 v2 §0 の表に既に `copy(x)` と書いてあり、そこが唯一の正解であること。
② `len(x)` / `str(x)` と同じ「値に対する道具は組み込み関数」という v1 の並びに合うこと。
③ メソッドにすると `list[T]` とクラスの両方に生やす必要があり、

**★ ownck を sema と分けた。** sema は順序を見ないパス、ownck は順序が本質のパス。
混ぜると両方読めなくなる。分けたことで「呼ばないだけで無効化できる」利点も得た。

**★ 追いかける単位を「変数」ではなく「場所（Place）」にした。**
`self.a` と `self.b` を別々に扱えるので、「`p.a` を移動しても `p.b` は使える」が
接頭辞の判定 3 行で表現できる。識別は名前ではなく **IR 名**（`%x` / `%x.1`）で行う
（兄弟スコープの同名変数は別の場所）。

**★ CFG は作らなかった。** `goto` が無いので AST の再帰で正しい解析ができる。
`while` だけ不動点反復（格子の高さが 2 なので最大 2 周。3 周目に変化したら
コンパイラのバグとして `internal_error` で落とす）。

`tests/selfhost.sh` が C 版と Polonium 版で 1 バイト単位に突き合わせている。

第29章で移植したら外す。

**★ 「通るべきテスト」にも `--deny-move` を付けた。**
違反が 1 件でもあればコンパイルが失敗するので、「警告が出ていないこと」を
`# EXIT:` だけで検証できる。**新しい検証の仕組みを足さずに済んだ。**

### つまずいたこと

**⚠️ `for` を書いただけで誤検出が出た。** 第11章の脱糖が作る `for.it.0 = names` が

これらは「対象を 1 回だけ評価する」ための別名なので、**借用として扱う**のが正しい
（仕様 v2 §3.1「`for` の要素は移動しない」）。名前に `.` が入るのは脱糖で作った
変数だけなので、それで見分けた。
**脱糖の側は直さない。** `for` を while に落とす判断（第11章）の利点のほうが大きい。

**⚠️ 不動点反復のたびに警告が出た。** 反復中は診断を止め（`quiet`）、
収束した入口でもう一度だけ解析して報告する形にした。

**⚠️ ループの中の移動で、note が使用箇所と同じ行を指してしまう。**

移動位置と使用位置が同じトークンなら「**前の繰り返しで**、ここで移動しています」に

## 2026-08-26 — 第23章 借用（保存・返却の禁止）

### やったこと

- 借用の根（`BorrowRoot` = 検査中の関数の仮引数）と、根をたどる判定を追加
- 移動の**文脈**（`MoveCtx`）を `move_expr` に渡し、`E-BORROW-1` / `-3` / `-4` を出し分け

- `--deny-borrow`（`--deny-move` とは別のスイッチ）

### 判断したこと（と理由）

**★ 局所変数への束縛（`t: str = s`）は許した。**
危険なのは「呼び出しより長生きすること」であって、別名そのものではない。
局所変数は呼び出しが終われば消えるので、`t` も借用として扱えば安全。
禁止すると名前を付け替えることすらできず、実用にならない。
**その代わり `bind_alias` で追跡する。** これが無いと、名前を変えるだけで検査をすり抜ける。

**★ 借用は「移動として記録しない」。**
記録すると、その後の使用ごとに `E-MOVE-1` が連鎖する。
**1 つの問題は 1 回だけ報告する。** 実際、この判断で `selfhost/` の
`E-MOVE-1` は 196 件 → 138 件に減った（検査は厳しくなったのに件数が減った）。

**★ `--deny-move` と `--deny-borrow` を分けた。**
1 つのスイッチにまとめると「移動だけエラーにして様子を見る」ができない。
第26章は章ごとに段階的に昇格させるので、**昇格の粒度＝検査の粒度**にしておく。

**★ グローバルは借用の根にしない。** プログラムが終わるまで生きているので、
どこへ保存しても寿命の問題が起きない（設計 §5.3）。

**★ `E-BORROW-1` を新しく割り当てた。** 仕様 §12 のコード体系は `E-BORROW-*` まで
決めてあり、`-3`（保存）と `-4`（返却）は設計 §5.1 で予約済みだった。
`own` 引数へ渡す形は「保存でも返却でもない移動」なので `-1` を使う。

**⚠️ 最初 `return xs[0]` を素通ししていた。** 第22章の「添字からは move out しない」

借用チェックを添字の免除より前に移した。

## 2026-08-29 — 第24章 可変性 `mut` と借用の衝突

### やったこと

- `BorrowRoot.is_mut` と `check_mut`：読み取り専用の借用への書き換えを `E-MUT-1` に（B3）
- `ArgRef` と二重ループ：1 つの呼び出しの中の借用の衝突を `E-BORROW-5` に（B1）
- `--deny-mut` / `--explain-mut`。option が 4 つになったので `OwnckOptions` にまとめた
- `tests/run_tests.sh` に `# EXPLAIN-MUT:` を追加
- テスト 10 本（落ちるべきもの 7 / 通るべきもの 3）

### 判断したこと（と理由）

**★ `mut` は「借用の権限」であって「規律」ではない。**
局所変数の再代入・`own` で受け取った値・ローカルで作ったオブジェクト・グローバルには
要求しない。Rust の `let mut` のような規律にすると、注釈だらけの言語になり D3 に反する。
実装も「借りものでなければ何も言わない」形にした。

**★ `init` の `self` は可変として扱う（`mut self` と書かなくてよい）。**
`init` が動いている間、そのオブジェクトはまだ誰にも貸していない。
貸し手がいないので「知らないうちに変わる」危険が起きない。
仕様 §4.2 の例（`def init(self, name: own str)`）とも一致する。
**例外が 1 つで済むことを確かめてから決めた**（第21章の `mut self` と同じ手順）。

**★ 書き換えの検出は「構文」ではなく「可変借用として渡したか」で見る。**
`fill(xs, 1)` は代入も append も書いていないが、渡した先で書き換わる。
`WR_ARG`（mut 引数への又貸し）を入れ忘れると、いくらでも回避できてしまう。

**★ `--explain-mut` の形式は `file:line:col: 説明` の 1 行 1 件（D13）。**
エディタから飛べて `grep` で読める、いちばん枯れた形式。JSON などの構造化形式は、

## 2026-08-29 — 第25章 解放（drop の挿入）

### やったこと

- ランタイムに `pl_drop_str` / `pl_drop_list` / `pl_drop_obj` を追加（**v1 で初めての `free`**）
- codegen にスコープ（`ScopeCtx`）を入れ、出口すべて（終端・`return`・`break` / `continue`）で解放
- 型ごとの解放関数を生成（`@drop.C` / `@drop.list.N`）
- ownck が `moved_out` / `binds_borrow` を AST に書き込み、codegen が読む
- `E-MOVE-2`（フィールドからの取り出しの禁止）と、それに合わせた**仕様の改訂**
- `--drop`（既定 off）、`make drop-asan`、テスト 7 本

### 判断したこと（と理由）

**★ D16：解放は `--drop` で opt-in にした。既定の IR は 1 バイトも変えない。**
この時点で `selfhost/` に 400 件の違反があるので、既定で解放するとコンパイラ自身が
二重解放で落ちる。opt-in にすれば `make bootstrap` と `make selfhost-test` が
そのまま緑のまま、解放そのものは小さなテストで今すぐ検証できる。
「検査を入れる」と「既存コードを直す」を混ぜない（D10）のコード生成版。

**★ D17：drop フラグ（`alloca i1`）を持たない。スロットの `null` で代用する。**
設計 §6.3 は Rust に倣ってフラグを想定していたが、Polonium の所有型はすべて
ポインタで、解放関数はすべて null を受け取れる。**移動したらスロットに null を書く**だけで、
分岐で片方だけ移動した場合も正しく動く。alloca も `br i1` も要らない。
設計ドキュメントのほうを改訂した。

**★ 「解放しないもの」を先に決めた。** 借用の引数・借りものを束縛した変数・
`for` のループ変数・**借用を返す関数の戻り値**（仕様 §4.5）・グローバル・リテラル・移動済み。
二重解放は「解放するものを間違えた」ではなく「**解放しないものを解放した**」で起きる。

**★ 借用を返す関数は、定義を先に読んで印を付ける。**
`s: str = lx.source()` の戻り値が所有か借用かは、呼び出し側からは見えない。
Rust ならライフタイムで表現するところを、**コンパイラが定義を読んで判断する**。
注釈を書かせない代わりに解析が背負う、という v2 の取引がここにも現れた。

**★ フィールドからの取り出し（`s = b.label`）を禁止した（E-MOVE-2）。**
許すとフィールドごとの drop フラグが必要になる。v2 は「フィールドは借りて使う」で足りる。
**コードより先に仕様（safety-spec.md §3.1）を直し**、第22章のテストを 1 本書き直した。

**★ `del` / `copy` / `pop` は次章以降に回した。**
新しい構文と解放を同じ章に入れると、落ちたときにどちらが原因か切り分けられない
（第21章で「構文だけ先に入れる」と決めたのと同じ判断）。

### つまずいたこと

**⚠️ 文字列リテラルを解放して落ちた。** リテラルは `.rodata` にあってヒープではない。
実行時にポインタだけで見分ける移植性のある方法が無いので、**長さのヘッダの
最上位ビット（1 << 62）を「静的」の印**にした。第15章で長さをヘッダに持たせておいた
判断が、10 章ぶんあとで効いた。印を立てるのは `--drop` のときだけ（既定の IR を変えないため）。

**⚠️ 上書き時に古い値を解放して、二重解放を作った。**
`t: str = xs[0]` の後の `t = xs[1]` で、古い `t`（= `xs[0]`）を解放していた。
借りものを束縛している変数では**古い値も他人のもの**。
印（`binds_borrow`）は解析の途中で立つので、**解析が終わってから代入ノードへ写す**
後処理を足した。**解析結果を codegen に渡すときは「いつ確定するか」を確かめること。**

**⚠️ `@drop.C` の中で自モジュールのメソッドを declare して「再定義」で落ちた。**
別モジュールのクラスのときだけ declare が要る。

**⚠️ 普通のテストでは二重解放を観測できない。** たまたま動いてしまう。
`make drop-asan`（`--drop` の IR をランタイムごと ASan でリンクして実行）を足した。
実際、上の 2 つの間違いはこれで見つけた。

| **解放の検査（ASan）** | ✅ 7 件すべて二重解放・解放後の使用なし |
| セルフホストの比較検証 | ✅ 全項目一致（既定の IR は不変） |
| **不動点** | ✅ stage2 == stage3 |
| 生成 IR（既定） | **1 バイトも変わらない**（変わるのは `--drop` のときだけ） |

## 2026-08-29 — 第27章 `raises` / `try` / `except`

### やったこと

- `raise` キーワードと `ND_TRY` / `ND_EXCEPT` / `ND_RAISE` を追加
- `raises` 節・`try` / `except` / `raise` の構文解析

- エラー出力引数（`ptr %err.out`）・タグ検査の分岐・`try` の振り分けを生成
- ownck に `try` / `raise` を教えた
- テスト 10 本。`tests/selfhost.sh` に `# STAGE1-SKIP:` を追加

### 判断したこと（と理由）

**★ 仕様に `raise` が無かったので足した。** §8 は「伝播する側」しか書いておらず、
**誰もエラーを起こせない**状態だった。仕様を書いたときは Rust の `?` に相当する
記法ばかり考えていて、`Err(...)` を**作る**側の構文が要ることに気づいていなかった。
**実装は仕様のレビューとして働く。**

**★ エラーは「出力引数 + タグ」で返す（設計どおり）。** 複合戻り値にすると
呼び出し・戻り値・main のラッパまで影響するが、出力引数なら**増えるのは引数 1 本**で、
既存の生成規則がそのまま使える。

**★ エラースロットは関数に 1 つ。** 呼んだ直後に必ずタグを見るので、
2 つの失敗が同時に生きていることはない。

**★ 失敗の飛び先は 2 通りだけ**（内側の try の振り分け / 伝播ブロック）。
どちらでもない場合は sema が禁止済みなので `unreachable` を出す。
**「起きないこと」を IR で表明しておくと、検査の穴がそのまま LLVM の検証で露見する。**

**★ `E-RAISE-3`（except の網羅性）は実装しなかった。**
捕まえていない型は「宣言していなければ呼び出しの時点でエラー」になるので、
網羅性は自動的に別のエラーとして現れる。**検査が 1 つ減り、エラーの位置も正確になる**
（「網羅していない try」ではなく「処理されない呼び出し」を指す）。

**★ stage1 が読めない構文のテストは、比較から外す印（`# STAGE1-SKIP:`）を作った。**
`# STAGE0-ONLY:`（run_tests 用）とは別の印にした。所有権のテストは構文が v1 のままなので
**比較はできる**（既定の IR は変わらない）。**印の意味を混ぜない。**

**⚠️ `raises A | B` の `|` を `T | None` と読んでしまった。**
`type_ref()` は第15章で nullable を読むように作ってある。
**同じ記号でも文脈で意味が違う**ので、`raises` 専用の 20 行の関数に分けた。
第15章で「型の `|` と式の `|` は読む関数が別だから迷わない」と書いた理屈がそのまま効いた。

**⚠️ `except ... as e` の変数に alloca を出し忘れた。**
`collect_allocas` は `ND_VARDECL` しか見ていなかった。
**さらに except の並びは `next` で繋がっている**ので、`if` の `else`（1 個）と同じ
つもりで書くと 2 番目以降が漏れる／二重に出る。

**⚠️ 伝播ブロックを常に出すと、`raises` を宣言していない関数で `%err.out` が
未定義になる。** 使われたときだけ出す形にした。

## 2026-08-29 — 第28章 `rc[T]`（共有所有）

### やったこと

- 型 `TY_RC` と `rc[T]` の解決、`rc(x)` の生成
- ランタイムに `pl_rc_new` / `retain` / `release` / `get`（と借用の数え札）
- ownck に「共有型は移動しない」を追加
- 参照の増減（retain / release）と `@drop.rc.N` の生成
- 自動デリファレンス（`node.name` がそのまま書ける）
- テスト 3 本（`make drop-asan` の網にも入れた）

### 判断したこと（と理由）

**★ 表現は「中身の埋め込み」ではなく「ポインタ 1 本」にした（設計 §7 を改訂）。**
Polonium の所有型はすべてポインタなので、埋め込むと型ごとのレイアウト計算が要る。
ポインタを持てば**どの型でも同じ形**になり、`rc(x)` は「既にある値に数え札を付ける」
1 命令で済む。

**★ D21：自動デリファレンスにして、`with borrow()` を書かせない。**
仕様 §7.2 は `with node.borrow() as n:` の形だったが、毎回書かせると
木やグラフのコードが読めなくなり、**`rc[T]` を用意した目的を裏切る**（D3 と同じ理由）。
代わりに失うのは「同時可変の実行時検査」。単一スレッドで添字も実行時検査するので
**メモリ安全は保てる**。ランタイム側の数え札は用意してあるので、`with` を入れるときに繋ぐ。

**★ retain は「場所から読んで別の場所に置くとき」だけ。**
`rc(...)` と関数の戻り値は新しい参照なので増やさない。ふつうの引数（借用）でも増やさない
（呼び出しの間は呼び出し側の参照が生きている）。
**retain と release は対**なので、`--drop` 無しのときはどちらも出さない。

**★ ownck では「移動しないが所有はする」。** `move_expr` の戻り値を第25章で
「束縛した側が所有するか」という意味にしておいたので、`return true` するだけで
**ムーブ検査は素通し・解放は挿入**という共有型の性質が表現できた。

### つまずいたこと

**⚠️ 新しい型を足すと、型を見る switch が芋づる式に見つかる。**
`llvm_type` / `llvm_mem_type` / `type_size` / `type_equal` / `type_name` /
`type_can_be_opt` / `elem_is_ptr` / `is_droppable`——**8 か所**。
どれも「default: UNREACHABLE()」か「明示的な列挙」なので、
**通らないと落ちるか、静かに間違える**。落ちるほうは即分かったが、
`is_droppable` の漏れは「解放が起きない」という**静かな間違い**で、
テストの出力（`drop a` が出ない）で気づいた。**列挙を足したら、列挙している場所を全部探す。**

**⚠️ `elem_is_ptr` の漏れは IR の型エラーになった**（`i64` のスロットに ptr を入れた）。
LLVM の検証が捕まえてくれたので、これは安全な壊れ方。

### 実測して確認したこと

| 何を | 結果 |
|---|---|
| C 版のテスト | ✅ 385 件パス（+3） |
| 解放の検査（ASan） | ✅ 11 件（**参照 3 つの共有が 1 回だけ解放される**ことを含む） |
| **不動点** | ✅ stage2 == stage3 |
| 第26章の行き止まり | ✅ 解けた（借りた rc をフィールドに保存できる） |

書き直し、**不動点を取り戻す**。手順は [tasks.md](tasks.md)。

- `selfhost/` に v2 の構文を移植：`raises` / `try` / `except` / `raise` / `rc[T]`
  （`ast.po` の定数・Node のフィールド・`parser.po` の解析・`--dump-ast` の出力）
- 意味づけを移植：エラー型 ID の割り当て、R1 / R2 / R4 / R5、`rc` の型付けと自動デリファレンス
- `diag.po` に `code` フィールドと `error_code_full` / `warn_full`
- 生成を移植：`%pl.err` の ABI・タグ検査・`try` の振り分け・`raise`・伝播・`rc`
- `# STAGE1-SKIP:` を全部外した（10 件 → 0 件）

### 判断したこと（と理由）

**★ 移植の順序は「比較できる順」。** `tests/selfhost.sh` はトークン → AST → 診断 → IR の
4 段で突き合わせる。構文を移せば AST の比較が、意味づけまで移せば診断の比較が戻る。
**段ごとに緑を取り戻せるので、壊れた場所が常に分かる。**

**★ 検査（ownck）と解放（--drop）の移植は後回しにした。**
どちらも**既定の出力を変えない**（検査は警告で `--check` では走らない、解放は `--drop` のみ）ので、
移植しなくても比較は一致する。先に `selfhost/` 自身を rc[T] で移行しないと、
移植した検査が自分自身に大量の警告を出して**「移植が正しいか」の判定を邪魔する**。
D10（検査はまず警告で入れる）と同じ形の判断。

**★ 移植中に言語を変えない。** `list` に `pop` が無いので try のスタックを
「最後の 1 つを外した新しいリスト」で作った（第13章の `module.po` と同じ手）。
`pop` を足すのは簡単だが、それは移植ではなく言語の変更になる。

### つまずいたこと

**⚠️ `raises` はキーワードなので、Polonium 版ではフィールド名に使えない。**
C 版の `Node.raises` は `Node.err_types` に改名した。
**自分の言語で自分を書くと、言語の制約が実装に跳ね返る。** IR は同じなので比較には影響しない。

**⚠️ 診断コード（`error[E-RAISE-1]`）まで一致させる必要があった。**
C 版は第22章で `Diag.code` を足していたが、Polonium 版には無かった。
第18章で決めた「メッセージ全体を比べる」がこの差を確実に捕まえた。

**⚠️ `rc[Node]` の構文解析は 1 行も要らなかった。** `type_ref` が `名前[要素型]` を
既に読める（`list[T]` と同じ道）。第10章の設計がここでも効いた。

### 実測して確認したこと

| 何を | 結果 |
|---|---|
| C 版のテスト | ✅ 385 件パス |
| セルフホストの比較 | ✅ トークン 425 / AST 383 / 型検査 236 / IR 236 / 実行 215。**raises / rc のケースも比較対象に戻った**（スキップ 10 件 → 0 件） |
| **不動点** | ✅ stage2 == stage3（`selfhost/` を約 400 行変えても IR は完全一致） |

③ `ownck` と解放の挿入を Polonium 版へ移植 →

## 2026-08-29 — 第30〜33章 OS へ（unsafe / ランタイム分割 / ベアメタル / 割り込み）

### やったこと

- **第30章**：`unsafe:` ブロックと `ptr[T]`、低レベルの 6 操作
  （`ptr_at` / `addr_of` / `peek8` / `peek64` / `poke8` / `poke64`）。`E-UNSAFE-1`
- **第31章**：ランタイムを `core.c`（libc 非依存）と `hosted.c`（フックの実装）に分割。
  `-c` / `--target=` / `PLC_CLANG` / `PLC_CFLAGS`、`pragma target` / `pragma no_runtime`
- **第32章**：RISC-V（QEMU virt）でベアメタル起動。`kernel/`（boot.s / link.ld /
  hooks.c / kernel.po）と `make kernel` / `make qemu` / `make qemu-test`
- **第33章**：`asm` / `asm_in` / `asm_out`、タイマ割り込み（CLINT）、UART 受信。
  **割り込みハンドラの中身を Polonium で書いた**

### 判断したこと（と理由）

**★ Q6 の決着：ベアメタルは RISC-V から。**
決め手は手元の道具だった——Apple の clang に RISC-V のバックエンドは無いが
Homebrew の LLVM にはある／x86 の ELF リンカは無いが `riscv64-elf-ld` はある／
`qemu-system-riscv64` の virt は `-bios none` で ELF を直接起動できる。
加えて **x86 は起動が複雑**（リアルモード → ロングモード、GDT…）で、
「OS を書く」ことを学ぶのに x86 の歴史を先に学ぶ必要はない。

**★ ランタイムは「もう 1 本書く」のではなく「4 つのフックに追い出す」。**
同じ処理を 2 か所に持つと必ずずれる。環境ごとに違うのは
alloc / free / write / panic の 4 つだけだった。
**おかげでカーネルの中でも `print` がそのまま使える**（第32章の実演）。

**★ `unsafe:` は「印」であって、生成には何も出さない。**
安全性の保証は「絶対に壊れない」ではなく「**壊れうる場所が限られていて、探せる**」こと。
`ptr[T]` の中身を `int` だけに絞ったのも同じ理由（メモリの中身と言語の型をずらさない）。

**★ 仕様 §10.4 の「プロファイル」は要らなかった。**
フックの設計にしたので、切り替えは `pragma no_runtime`（C の main ラッパを出さない）
1 つで足りた。**設計を変えたら、仕様の一部が不要になった**という例。

**★ アセンブリで書くのは 2 か所だけ**（`_start` と `trap_entry`）。
どちらも「スタックやレジスタそのものを扱う」ので高級言語では書けない。
逆に言えば、**それ以外は全部 Polonium で書けた**。

### つまずいたこと

**⚠️ `-mcmodel=medany` が要る。** 既定（medlow）は「アドレスは下位 2GB」前提なので、
0x80000000 に置くと `relocation truncated to fit` で落ちる。

**⚠️ シンボル名はファイル名で決まる。** `kernel/main.po` にしたら `@main.main` になり、
`boot.s` の `call kernel.main` がリンクできなかった。**ファイル名がそのまま ABI**
（第13章のモジュール修飾の帰結）。`kernel/kernel.po` に改名して解決。

**⚠️ `%0` は LLVM IR では `$0`。** C と同じ `%0` を書いてもらい、codegen が直す形にした。
RISC-V では `%` が `%hi(...)` の再配置指定にも使われるので、そのままだとアセンブラが
別物として読む。

**⚠️ freestanding でも clang は `memcpy` を呼ぶ。** 「明らかにコピー」のループを
置き換えるため。libc の無い世界では相手も自分で用意する。

**⚠️ zsh は変数を単語に分けない。** `clang $RVFLAGS` がフラグ全体で 1 引数になり、
`invalid arch name 'rv64g -mabi=lp64 …'` で気づいた（bash とはここが違う）。

**⚠️ `mtimecmp` を入れ直さないと割り込みが 1 回で終わる**（というより再発し続ける）。
テストで `tick 1` と `tick 3` の両方を見ているのはそのため。

### 実測して確認したこと

| 何を | 結果 |
|---|---|
| C 版のテスト | ✅ 388 件パス（+3） |
| 解放の検査（ASan） | ✅ 11 件 |
| **ベアメタル（QEMU / RISC-V）** | ✅ `make qemu-test` が 7 項目すべて一致 |
| カーネルの中身 | ✅ `print` / `for` / `range` / `str` 連結 / `list[str]` が動く |
| 割り込み | ✅ タイマ割り込みを 3 回受け、ハンドラで `print` できた |
